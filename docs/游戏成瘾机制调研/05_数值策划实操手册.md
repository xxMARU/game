# 数值策划实操手册 — 成瘾机制数值设计

> **文档定位**：本手册面向数值策划从业者，提供可直接落地的数值设计模板、公式与参数参考。所有数值均基于行业主流产品的逆向分析与实战经验总结，覆盖奖励系统、概率系统、经济系统、难度曲线、养成系统、体力系统与版本迭代规划七大核心模块。
>
> **使用说明**：文中"标准日收入"指一名活跃免费玩家每日通过正常游玩获得的平均资源价值，记作 **1.0 SDI（Standard Daily Income）**。各品类游戏可根据自身经济体系换算为具体数值。

---

## 一、奖励系统数值设计

奖励系统是成瘾机制的基石。玩家持续游玩的核心驱动力来自"付出→获得"循环中的正反馈。数值策划的核心任务是精确控制奖励的**价值量级、发放频率、递减曲线与随机性**，使玩家在每一个时间切片上都维持着"刚好满足但又想要更多"的心理状态。

### 1.1 奖励价值分层体系

奖励的价值感知不取决于绝对数值，而取决于其在玩家"心理账户"中的相对位置。我们将奖励分为 **6 个等级**，以标准日收入（SDI = 1.0）为基准单位进行量化：

| 等级 | 价值范围（SDI） | 典型场景 | 心理作用 | 频率要求 |
|------|----------------|----------|----------|----------|
| **微型奖励** | 0.01 – 0.05 | 每次操作的即时反馈：金币飘字、少量经验、连击计数 | 维持操作节奏感，产生"每一下都有收获"的错觉 | 每10-30秒1次 |
| **小型奖励** | 0.05 – 0.15 | 完成单个任务/击杀一组怪物/采集一次资源 | 短期目标达成感，驱动"再做一个"行为 | 每3-5分钟1次 |
| **中型奖励** | 0.15 – 0.50 | 完成日常任务包/通关一个关卡/完成一次副本 | 阶段性成就感，标记游玩进程的"里程碑" | 每15-30分钟1次 |
| **大型奖励** | 0.50 – 1.50 | 每日核心活动奖励：副本首通、竞技场结算、Boss击杀 | 每日游玩的核心目标，驱动"今天一定要完成"的行为 | 每日1-3次 |
| **超大型奖励** | 1.50 – 5.00 | 周期性里程碑：周任务总包、赛季周结算、公会战奖励 | 中期目标驱动，维持以"周"为单位的游玩习惯 | 每周1-2次 |
| **终极奖励** | 5.00 – 20.00 | 赛季终极奖励、全服首杀成就、限定收藏品、满级突破 | 长期目标锚定，成为玩家自我叙事的"高光时刻" | 每月/每赛季 |

**设计原则**：

1. **金字塔分布**：微型奖励的发放次数应是小型的4-6倍，小型是中型的3-5倍，以此类推。形成"频繁的小满足 + 偶尔的大惊喜"的体验节奏。
2. **价值锚定**：玩家对奖励价值的判断依赖于最近获得的参照物。在发放大型奖励前，应先发放2-3个小型奖励，使大型奖励的"对比效应"最大化。
3. **情感包装**：数值相同的奖励，通过不同的视觉/音效包装可产生2-5倍的感知价值差异。金色文字 > 紫色文字 > 白色文字；开宝箱动画 > 直接入包。

### 1.2 奖励频率与间隔设计

频率设计的核心目标是：**每一分钟的游玩都有"即将获得奖励"的期待感**。

| 奖励等级 | 最优间隔 | 可接受范围 | 超出则流失风险上升 |
|---------|---------|-----------|------------------|
| 微型 | 15秒 | 10-30秒 | >45秒 |
| 小型 | 4分钟 | 3-5分钟 | >8分钟 |
| 中型 | 20分钟 | 15-30分钟 | >45分钟 |
| 大型 | 每日1-2次 | 1-3小时游玩获1次 | >4小时 |
| 超大型 | 每周1次 | 每周1-2次 | >2周无 |
| 终极 | 每赛季1次 | 每月-每赛季 | >3个月无 |

**黄金比例（单次会话模型）**：

一次典型的游戏会话时长为 **20-45 分钟**，在此期间应至少包含：
- **微型奖励** ≥ 20 次（维持持续的正反馈感）
- **小型奖励** ≥ 5 次（每完成一个子任务就有回报）
- **中型奖励** ≥ 1 次（本次会话的"核心收获"）
- **大型奖励接近信号** ≥ 1 次（进度条推进到80%+，驱动"下次再来"）

**会话终止点设计**：玩家退出游戏时，应至少有1个"未完成的中型奖励进度"（蔡格尼克效应），使其在下次打开游戏时有明确的即时目标。

### 1.3 奖励递减与通胀控制

任何奖励系统都面临两个天敌：**玩家的适应性**（同一奖励越来越无感）和**经济通胀**（数值越来越大导致丧失意义）。

#### 边际效用递减模型

同一类型奖励连续获得 N 次后，玩家的主观价值感知遵循递减曲线：

```
主观价值(N) = 客观价值 × 1/(1 + 0.2N)
```

| 连续获得次数N | 主观价值系数 | 解读 |
|-------------|------------|------|
| 1 | 0.83 | 第一次获得，几乎等于客观价值 |
| 3 | 0.63 | 价值感下降约1/3 |
| 5 | 0.50 | 价值感减半 |
| 10 | 0.33 | 仅剩1/3价值感 |
| 20 | 0.20 | 基本"麻木" |

**对策——奖励类型轮换**：
- 将奖励分为 4-6 个类型池（货币、经验、材料、装备、外观、功能道具）
- 每 **7-14 天** 进行一次轮换，改变当期主推奖励类型
- 同一奖励类型连续出现不超过 3-5 次
- 采用"惊喜奖励"机制：在固定奖励之外有15%-25%概率出现非常规奖励

#### 经济系统通胀控制

| 指标 | 健康范围 | 预警线 | 危险线 |
|------|---------|--------|--------|
| 月通胀率 | 3%-5% | 5%-8% | >10% |
| 资源产出/消耗比 | 0.8-1.2 | 1.2-1.5 | >1.5 |
| 顶级货币存量中位数 | 3-7日消耗量 | 7-14日 | >14日 |

**资源回收机制（Resource Sink）设计**：

| 回收机制 | 回收效率 | 适用场景 |
|---------|---------|---------|
| 装备强化消耗 | ★★★★★ | 主要回收通道，消耗50-70%的日常货币产出 |
| 交易税（5%-15%） | ★★★★ | 有交易系统的游戏必备 |
| 修理费/耐久度 | ★★★ | 传统MMO常用 |
| 限时物品过期 | ★★★ | 活动货币/限时buff |
| 外观/收藏消耗 | ★★ | 非战力消耗，吸引收集型玩家 |
| 转服/改名费用 | ★ | 低频但高单价回收 |

### 1.4 随机奖励概率设计公式

随机性是成瘾机制中最强力的工具——可变比率强化调度（Variable Ratio Schedule）是所有强化调度中消退最慢的。但"纯随机"会造成极端体验（欧洲人vs非洲人），因此需要使用伪随机和保底系统来收窄体验方差。

#### 真随机 vs 伪随机分布（PRD）

**真随机（True Random）**：每次独立事件，概率恒定。
- 优点：实现简单
- 缺点：方差大，10%概率事件可能30次不触发（概率4.2%）

**伪随机分布（Pseudo-Random Distribution, PRD）**：

PRD 的核心公式：

```
P(N) = C × N
```

其中 C 为调整常数，N 为自上次触发以来的累计次数。当 P(N) ≥ 100% 时必定触发，触发后 N 重置为 0。

| 目标概率 | PRD 的 C 值 | 首次触发概率 | 期望触发次数 | 最大无触发次数 |
|---------|------------|------------|------------|--------------|
| 5% | 0.003 | 0.3% | 20.0 | ~38 |
| 10% | 0.015 | 1.5% | 10.0 | ~26 |
| 15% | 0.032 | 3.2% | 6.7 | ~18 |
| 25% | 0.075 | 7.5% | 4.0 | ~14 |
| 50% | 0.302 | 30.2% | 2.0 | ~4 |

PRD 的优势在于：**降低了极端运气的影响**，保证了体验方差在可控范围内，同时保留了足够的随机感。

#### 保底递增公式（Pity System）

以原神模型为代表的软保底+硬保底体系：

```
P(n) = P_base + max(0, (n - soft_pity) × increment)
```

**参数说明**：
- `P_base`：基础概率（如0.6%）
- `soft_pity`：软保底起始抽数（如第73抽）
- `increment`：每抽递增概率（如6%）
- 硬保底：当 P(n) ≥ 100% 时必定触发（如第90抽）

**原神5星角色保底模型详解**：

```
P(n) = 0.006 + max(0, (n - 73) × 0.06)
```

| 抽数 n | 触发概率 P(n) | 累计触发概率 | 解读 |
|-------|-------------|------------|------|
| 1-73 | 0.6% | ~35% | 基础概率区间 |
| 74 | 6.6% | ~38% | 软保底启动 |
| 76 | 18.6% | ~52% | 过半玩家已触发 |
| 80 | 42.6% | ~80% | 大部分玩家已触发 |
| 85 | 72.6% | ~96% | 绝大多数已触发 |
| 90 | 100% | 100% | 硬保底，必定触发 |

**期望抽数**：约 **62.5 抽**（考虑保底后远低于 1/0.006 ≈ 167 抽）

#### 期望值计算

- 简单随机：E(X) = 1/P
- PRD 系统：需蒙特卡洛模拟（10万次+），因每次概率随状态变化
- 保底系统：E(X) = Σ[n × P(首次在第n抽触发)]，可解析求解或模拟

## 二、概率系统设计

概率系统（Gacha/抽卡/掉落）是现代F2P游戏商业化的核心引擎。数值策划需要在"足够刺激吸引投入"和"不至于引发玩家暴怒"之间找到精确的平衡点。

### 2.1 抽卡/Gacha 概率设计模板

以下是业界主流的抽卡概率设计参数范围，涵盖三档品质：

| 品质 | 基础概率 | 综合概率(含保底) | 软保底起始 | 硬保底 | 期望抽数 | 单抽价格(元) | 期望花费(元) |
|------|---------|----------------|-----------|--------|---------|-------------|-------------|
| **5星/SSR** | 0.6%-1.0% | 1.2%-1.8% | 60-75抽 | 80-90抽 | 62-70抽 | 18-20 | 1100-1400 |
| **4星/SR** | 5.0%-6.0% | 8.0%-10.0% | 8-9抽 | 10抽 | 8-9抽 | 18-20 | 144-180 |
| **3星/R** | 剩余概率(~93%) | N/A | N/A | N/A | N/A | 18-20 | 18-20 |

**关键设计参数详解**：

**① 基础概率（Base Rate）**
- SSR基础概率的行业标准区间为 **0.6%-3.0%**
  - 保守派（原神、FGO）：0.6%-0.7%，依赖保底系统，期望花费高
  - 中间派（明日方舟、碧蓝航线）：1.0%-2.0%，适中体验
  - 激进派（某些休闲卡牌）：2.0%-3.0%，靠角色/卡牌数量制造稀释

**② 综合概率（Consolidated Rate）**
- 包含保底机制后的等效概率
- 计算方法：模拟100万次抽卡，统计SSR总出现次数/总抽数
- 综合概率通常是基础概率的 **1.5-2.5 倍**

**③ Up机制（Rate-Up / Pick-Up）**
- 当期限定角色在SSR中的占比：50%-75%
- "小保底"失败后"大保底"必出UP角色（原神模型）
- 期望获取特定UP角色的抽数：约 **105-120 抽**（含50%大小保底）

**④ 十连保底（10-Pull Guarantee）**
- 每10次抽卡至少保底1个SR（4星）
- 这使得SR的综合概率从5%提升至约10%
- 心理作用：消除"十连全蓝"的极端负面体验

#### 抽卡系统收入预估模型

```
月抽卡收入 = DAU × 付费率 × ARPPU_抽卡
         = DAU × 付费率 × (月均抽数 × 单抽价格)
```

- 重度Gacha游戏月均抽数（付费用户）：80-200抽
- 轻度Gacha游戏月均抽数（付费用户）：30-80抽
- 免费玩家月均获取抽数：30-50抽（通过活动/任务/维护补偿）

### 2.2 掉落概率设计模板

掉落系统与抽卡不同，掉落与**游戏内容进度**强绑定，玩家通过"刷"特定内容获取特定奖励。

#### Boss 掉落概率模板

| 稀有材料 | 15%-30% | 20%-40% | 30%-50% | 25%-45% |
| 稀有装备 | 5%-15% | 8%-20% | 10%-25% | 5%-10% |

|---------|---------|------------|------------|---------|

| 铁质宝箱 | 常见 | 0.03-0.05 | 15% | 中量金币+材料+低概率装备 |
| 银质宝箱 | 不常见 | 0.05-0.10 | 30% | 较多金币+稀有材料 |
| 金质宝箱 | 稀有 | 0.10-0.25 | 60% | 大量金币+稀有装备 |
| 传说宝箱 | 极稀有 | 0.25-0.50 | 90% | 海量金币+传说级物品 |

#### 暗掉率机制（Hidden Drop Rate / Newcomer Protection）

为改善新手前期体验，许多游戏在不公开的情况下提升新玩家的掉落率：

| 保护阶段 | 生效条件 | 掉落率倍率 | 持续时间 |
|---------|---------|-----------|---------|
| 极早期 | 账号创建<24小时 | 3.0-5.0× | 首次击杀各Boss |
| 早期 | 等级<20级 | 2.0-3.0× | 约1-3天 |
| 过渡期 | 等级20-40级 | 1.5-2.0× | 约3-7天 |
| 回归保护 | 离线>7天 | 1.5-2.0× | 回归后48-72小时 |
| 常规 | 正常玩家 | 1.0× | 永久 |

**设计注意**：暗掉率必须严格保密。一旦被玩家社区发现并确认，将引发信任危机。建议通过"首通奖励"等公开机制替代部分暗掉率功能。

### 2.3 概率感知设计

人类天生不擅长直觉性地理解概率——这既是挑战也是机会。

#### 玩家感知概率 vs 实际概率的偏差

| 实际概率 | 玩家感知概率 | 偏差倍率 | 心理机制 |
|---------|------------|---------|---------|
| 1% | 3%-5% | 3-5× | 可得性偏差——"别人都抽到了" |
| 5% | 10%-15% | 2-3× | 过度自信——"我应该差不多了" |
| 25% | 30%-40% | 1.2-1.6× | 轻度高估 |
| 50% | 45%-55% | ~1× | 感知最准确 |
| 75% | 60%-70% | 0.8-0.93× | 开始低估 |
| 95% | 80%-85% | 0.84-0.89× | 墨菲定律焦虑——"万一失败了" |
| 99% | 90%-95% | 0.91-0.96× | "总有人是那1%" |

#### 概率展示策略

| 展示方式 | 玩家理解度 | 适用场景 | 示例 |
|---------|-----------|---------|------|
| 百分比 | ★★★ | 高概率事件(>20%) | "成功率70%" |
| 分数 | ★★★★ | 中低概率事件 | "每10次约出1次" |
| 期望次数 | ★★★★★ | 低概率事件(<5%) | "平均约65抽出金" |
| 可视化 | ★★★★★ | 所有场景 | 进度条/填充图标 |
| 历史记录 | ★★★★ | 需要信任的场景 | "你最近100抽出了2个SSR" |

**保底机制对心理安全感的影响**：
- 有保底系统的游戏，玩家消费意愿比无保底系统高 **40%-80%**
- 原因：保底将"赌博"转化为"投资"——玩家知道自己的每一抽都在"积累进度"
- 保底计数器的UI可视化（如"距保底还差X抽"）可进一步提升15%-25%的抽卡转化率

## 三、经济系统数值设计

经济系统是游戏长线运营的"血液循环系统"。设计合理的经济系统可以自然地引导玩家行为、调控游戏节奏、创造付费需求。设计失败则会导致通胀失控、贫富分化、劣币驱逐良币等一系列连锁崩坏。

### 3.1 货币体系设计

现代F2P游戏普遍采用 **多层货币体系**，每种货币承担不同的功能角色：

| 货币类型 | 典型名称 | 获取方式 | 主要用途 | 流通控制 |
|---------|---------|---------|---------|---------|
| **硬通货（付费货币）** | 钻石/水晶/原石 | 充值（主）+ 少量免费产出 | 抽卡、加速、购买特权 | 严格控制免费产出量 |
| **软通货（免费货币）** | 金币/铜钱/摩拉 | 游戏活动、任务、关卡掉落 | 升级、强化、购买NPC商品 | 通过消耗机制回收 |
| **活动货币** | 活动代币/奖章 | 限时活动产出 | 兑换限定奖励 | 活动结束后清零或低价回收 |
| **竞技货币** | 荣誉/竞技币 | PVP活动结算 | 兑换PVP专属奖励 | 赛季重置或封顶 |
| **公会货币** | 贡献/公会币 | 公会活动/捐献 | 公会商店兑换 | 公会等级/人数限制产出 |

#### 各货币产出/消耗比例控制

**软通货（金币）产出设计**：

```
软通货日产出量 = 日消耗需求 × 0.8 ~ 1.2
```

- **略微不足（0.8-0.95×）**：最优设计区间。玩家感觉"差一点点"，促进以下行为：
  - 优先级选择（不能所有东西都升，要有取舍）
  - 效率优化（寻找更高效的金币获取方式）
  - 轻度付费转化（月卡用户多获得的金币刚好补齐缺口）
- **基本平衡（0.95-1.05×）**：安全区间，适合休闲游戏
- **略有盈余（1.05-1.2×）**：适用于游戏早期，给新玩家舒适体验

**硬通货（钻石）免费产出设计**：

```
硬通货免费日产量 = 付费用户日均消费 × 0.15 ~ 0.25
```

- 免费玩家通过每日任务、成就、维护补偿等获得的硬通货
- 应足以支撑每 **2-3 周** 进行一次"关键消费"（如一次十连抽）
- 但不足以与月卡/通行证用户持平（月卡用户获取量约为免费的 **2.5-4 倍**）

### 3.2 物品定价模型

#### 基础定价公式

```
价格 = 基础成本 × 稀有度系数 × 需求系数 × 时效系数
```

| 参数 | 定义 | 取值参考 |
|------|------|---------|
| 基础成本 | 生产/获取该物品的平均资源投入 | 根据制作材料或掉落期望消耗 |
| 稀有度系数 | 品质等级带来的溢价 | 见下表 |
| 需求系数 | 当前版本对该物品的需求程度 | 0.5-2.0，随版本更新调整 |
| 时效系数 | 是否限时/赛季性物品 | 常驻1.0 / 限时1.3-1.8 / 绝版2.0-5.0 |

**稀有度系数参考表**：

| 品质等级 | 稀有度系数 | 相对普通品的价值 | 典型获取难度 |
|---------|-----------|----------------|------------|
| 普通/白色 | 1.0 | 基准 | 随处可得 |
| 优秀/绿色 | 1.5-2.0 | 基准的1.5-2倍 | 轻松获取 |
| 稀有/蓝色 | 2.0-3.0 | 基准的2-3倍 | 需要一定投入 |
| 史诗/紫色 | 5.0-8.0 | 基准的5-8倍 | 需要显著投入 |
| 传说/橙色 | 12.0-20.0 | 基准的12-20倍 | 大量投入或运气 |
| 神话/红色 | 30.0-50.0 | 基准的30-50倍 | 极度稀有 |

#### 价格锚定设计

**锚定效应（Anchoring Effect）** 是定价策略的核心心理武器：

1. **原价展示**：所有折扣商品必须展示原价（划线价），且原价应为实际售价的 **2-3 倍**
2. **高价锚点**：商城第一个显示的物品应是最贵的（如648元礼包），使后续98元/30元礼包显得"便宜"
3. **比较锚点**：在推荐商品旁放置一个"性价比明显更低"的选项，使推荐商品显得"划算"

#### 折扣心理学

| 折扣深度 | 玩家感知 | 购买转化效果 | 使用建议 |
|---------|---------|------------|---------|
| <20% | "没什么优惠" | 几乎无效 | 不建议使用 |
| 20%-30% | "小优惠" | 效果有限 | 常规小促销 |
| **30%-50%** | **"值得买"** | **最优区间** | **主力促销活动** |
| **50%** | **"半价！"** | **最强心理触发** | **重大活动/首充** |
| 50%-70% | "大促销" | 效果好但降低品质感 | 限时闪购 |
| >70% | "是不是要关服了" | 短期爆发但损害品牌 | 极少使用/清仓 |

**最优折扣深度**：**50%（半价）** 是效果最强的心理触发词。"半价"比"47折"或"53折"的转化率高出 **30%-60%**，因为"一半"是人类最直觉的数学概念。

### 3.3 资源产出与消耗平衡表

以下为通用的资源产出消耗平衡表模板：

| 资源名称 | 日产量(免费) | 日产量(月卡) | 日产量(大月卡) | 日消耗(推荐) | 周消耗峰值 | 月通胀率控制 |
|---------|------------|------------|-------------|------------|-----------|------------|
| 金币 | 50,000 | 75,000 | 100,000 | 55,000 | 450,000 | ≤3% |
| 钻石 | 60 | 150 | 250 | 80(抽卡) | 800 | ≤1% |
| 经验材料 | 200 | 300 | 400 | 180 | 1,500 | ≤5% |
| 强化石 | 30 | 50 | 80 | 35 | 300 | ≤3% |
| 体力 | 180 | 240 | 300 | 180 | 1,400 | 0%(固定回复) |
| 突破材料 | 5 | 8 | 12 | 4 | 35 | ≤2% |

**平衡表使用方法**：
1. 每周审计一次实际数据 vs 设计数据的偏差
2. 偏差超过 ±15% 时需要介入调整
3. 关注"存量中位数"指标——玩家中位数存量 = 3-7日消耗量为健康值
4. 新版本上线前模拟资源冲击：新消耗点是否会导致资源缺口过大

### 3.4 交易系统设计

#### 交易税率设计

```
最优税率 = 5% ~ 15%
```

| 税率 | 回收效率 | 玩家接受度 | 适用场景 |
|------|---------|-----------|---------|
| 3%-5% | 低 | 高 | 交易频繁的游戏（MMORPG） |
| 5%-10% | 中 | 中 | 多数游戏的最优区间 |
| 10%-15% | 高 | 低 | 需要强力回收的成熟游戏 |
| >15% | 极高 | 极低 | 不建议，会抑制交易活跃度 |

#### 拍卖行设计参数

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 上架手续费 | 物品估价的1%-3% | 防止大量低价垃圾上架 |
| 成交手续费 | 成交价的5%-10% | 主要回收通道 |
| 上架时长 | 12-48小时 | 过短无法成交，过长占据位置 |
| 底价限制 | 系统估价的50%-200% | 防止异常低价洗钱/RMT |
| 一口价限制 | 系统估价的80%-500% | 防止天价炒作 |
| 每人上架数量 | 5-20个 | 防止囤货垄断 |

#### 防通胀机制矩阵

| 机制 | 效力 | 实施难度 | 玩家感知 |
|------|------|---------|---------|
| NPC商店价格锚定 | ★★★★ | 低 | 正面——提供价格参考 |
| 交易税回收 | ★★★★ | 低 | 中性——行业惯例 |
| 装备绑定机制 | ★★★★★ | 低 | 负面——限制自由交易 |
| 强化消耗 | ★★★★★ | 中 | 正面——养成体验的一部分 |
| 限购/限量 | ★★★ | 低 | 中性——制造稀缺感 |
| 赛季重置 | ★★★★★ | 高 | 争议——部分玩家抵触 |
| 黑市NPC回收 | ★★★ | 中 | 正面——提供兜底出货渠道 |

## 四、难度曲线设计

难度曲线是"心流体验"的数值化表达。设计合理的难度曲线可以让玩家始终处于"既不无聊也不焦虑"的最佳心理状态，这是维持长期粘性的关键机制。

### 4.1 心流通道数值模型

**心流（Flow）** 发生在"挑战难度"与"玩家技能"之间达到动态平衡时。数值化表达为：

```
D(n) = S(n) × (1 + δ)
```

其中：
- `D(n)` = 第n关/第n次挑战的难度值
- `S(n)` = 玩家在第n次挑战时的预期技能/战力水平
- `δ` = 难度偏移量

| δ 值范围 | 玩家体验 | 设计意图 |
|---------|---------|---------|
| -0.30 以下 | 极度无聊 | 避免 |
| -0.30 ~ -0.15 | 轻松愉快 | 休息关卡/奖励关 |
| **-0.15 ~ +0.15** | **心流状态** | **核心游玩体验** |
| +0.15 ~ +0.30 | 有挑战感 | Boss关/精英关 |
| +0.30 ~ +0.50 | 困难/需要策略 | 高难本/成就挑战 |
| +0.50 以上 | 极度挫败 | 避免（或仅用于排行榜顶端内容） |

#### 关卡难度增长率

难度增长率应随游戏阶段变化，呈现"S型曲线"：

| 游戏阶段 | 关卡范围（示例） | 每关难度增长率 | 设计理由 |
|---------|---------------|-------------|---------|
| **新手期** | 第1-20关 | 3%-5% | 温和引导，建立信心 |
| **成长期** | 第21-100关 | 5%-8% | 稳步提升，培养技能 |
| **挑战期** | 第101-200关 | 8%-12% | 深度挑战，要求策略 |
| **大师期** | 第200+关 | 2%-5% | 增长放缓，转为横向挑战 |

**累计难度增长示例**（以第1关难度=100为基准）：

| 关卡 | 新手期(4%/关) | 成长期(6%/关) | 挑战期(10%/关) |
|------|-------------|-------------|-------------|
| 第1关 | 100 | — | — |
| 第10关 | 148 | — | — |
| 第20关 | 219 | — | — |
| 第50关 | — | 544 | — |
| 第100关 | — | 1,842 | — |
| 第150关 | — | — | 11,739 |
| 第200关 | — | — | 117,391 |

#### 难度峰谷设计（Tension-Release Pattern）

持续的难度爬升会导致疲劳。最优节奏是"波浪形"：

```
每 3-5 个"爬坡"关卡 → 1 个"休息"关卡（难度回落20%-30%）
```

**节奏模板**（以5关为一个周期）：

| 关卡序号 | 难度系数 | 类型 | 玩家体验 |
|---------|---------|------|---------|
| N+1 | 1.00× | 标准关 | 正常挑战 |
| N+2 | 1.06× | 递增关 | 略有难度 |
| N+3 | 1.12× | 递增关 | 需要集中精力 |
| N+4 | 1.20× | 高峰关/Boss | 紧张刺激 |
| N+5 | 0.85× | 休息关 | 轻松愉快+丰厚奖励 |

### 4.2 动态难度调整（DDA）参数

动态难度调整（Dynamic Difficulty Adjustment）是游戏在运行时根据玩家表现自动微调难度的系统。其核心原则是：**让玩家感觉自己在进步，而不是游戏在变容易**。

#### DDA 触发条件

| 触发事件 | 调整方向 | 调整时机 |
|---------|---------|---------|
| 连续失败 ≥ 3次 | 降低难度 | 下一次尝试立即生效 |
| 连续失败 ≥ 5次 | 大幅降低难度 + 提供辅助 | 立即生效 + 弹出提示 |
| 连续成功 ≥ 5次 | 提升难度 | 下一关卡开始生效 |
| 连续成功 ≥ 8次 | 大幅提升难度 | 立即生效 |
| 通关时间远低于预期（<50%） | 提升难度 | 下一关卡 |
| 通关时间远高于预期（>200%） | 降低难度 | 下一次尝试 |
| 受伤率过高（>血量80%） | 轻微降低 | 本局内实时调整 |

#### DDA 调整参数

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 单次调整幅度 | ±5%-10% | 每次触发的调整量 |
| 累计调整上限 | ±30% | 无论连续多少次失败/成功，不超过此范围 |
| 调整衰减 | 每成功1次回收5% | 防止难度被持续拉低 |
| 重置条件 | 关卡切换/登出重登 | 新关卡从基准难度开始（保留少量倾向） |
| 调整维度 | 多维度联动 | 不仅调HP，同时调AI行为/掉落率/辅助提示 |

#### DDA 隐蔽性设计

**核心原则：DDA 对玩家必须完全不可感知。**

| 调整维度 | 隐蔽方式 | 玩家感知 |
|---------|---------|---------|
| 敌人HP | ±10%-20% | 不可感知（战斗时间变化在自然波动范围内） |
| 敌人攻击力 | ±10%-15% | 不可感知（伤害数字变化不大） |
| 敌人AI行为 | 降低攻击频率/增加失误率 | 感觉"自己发挥更好了" |
| 掉落率 | 提升20%-50% | 感觉"运气变好了" |
| 隐蔽辅助 | 扩大判定框/延长无敌帧 | 感觉"手感变好了" |
| 环境辅助 | 增加回复道具/减少陷阱 | 感觉"这一关设计合理" |

**经典案例：《生化危机4》（RE4）自适应难度系统**：
- 根据玩家受伤频率、弹药消耗率、击杀效率综合评分
- 实时调整敌人HP（±20%）、攻击力（±15%）、出现频率、弹药掉落率
- 目标：让所有玩家都感觉"刚好能过"

### 4.3 Boss 战难度设计

Boss 战是游戏难度设计的"高光时刻"——它需要给玩家带来紧张、刺激、成就感，而非绝望。

#### Boss 血量公式

```
Boss_HP = 玩家平均DPS × 预期战斗时长(秒) × 容错系数
```

| 参数 | 说明 | 取值范围 |
|------|------|---------|
| 玩家平均DPS | 推荐等级/战力下的平均每秒伤害 | 从数据采集 |
| 预期战斗时长 | 设计师预期的理想战斗时长 | 见下表 |
| 容错系数 | 考虑玩家需要闪避/走位的时间 | 1.2-1.5 |

**预期战斗时长参考**：

| Boss 类型 | 预期战斗时长 | 典型场景 |
|----------|------------|---------|
| 小Boss（精英怪） | 30秒-2分钟 | 野外/小型副本 |
| 中Boss（副本Boss） | 2-5分钟 | 普通副本/日常本 |
| 大Boss（团队Boss） | 5-10分钟 | 团队副本 |
| 终极Boss（Raid Boss） | 10-20分钟 | 高难度团队内容 |
| 马拉松Boss | 20-40分钟 | 极限挑战/排行榜内容 |

#### Boss 攻击模式周期

```
一个完整攻击循环 = 30-60秒
```

| 循环阶段 | 时长占比 | 内容 |
|---------|---------|------|
| 安全窗口（输出期） | 40%-50% | Boss使用可预测的低威胁技能，玩家全力输出 |
| 威胁期（走位期） | 30%-35% | Boss使用范围技能/高伤害技能，玩家需要走位 |
| 转场期（机制期） | 15%-25% | Boss切换阶段/触发特殊机制 |

#### 容错设计

**核心原则**：玩家在 DPS 不足理论值 80% 的情况下，仍然可以通过（需要更长时间和更精准操作）。

```
通关最低DPS阈值 = Boss_HP / (时间限制 × 0.8)
推荐DPS = 最低DPS × 1.2
```

这意味着推荐战力的玩家有 **20% 的安全边际**，即使操作不完美也能通关。

## 五、养成系统数值设计

养成系统是"沉没成本"的制造机——玩家在角色/装备上投入越多时间和资源，离开的心理成本就越高。优秀的养成系统需要让玩家"每一天都有可感知的进步"，同时确保"永远有下一个可以追求的目标"。

### 5.1 等级系统

#### 总等级数设计

| 游戏类型 | 推荐总等级数 | 到满级天数(免费) | 每日游玩时间假设 |
|---------|------------|----------------|---------------|
| 轻度休闲 | 30-60级 | 30-60天 | 15-30分钟 |
| 中度RPG/卡牌 | 60-120级 | 60-180天 | 30-60分钟 |
| 重度MMORPG | 100-200级 | 120-365天 | 60-120分钟 |
| 无限制(赛季重置) | 50-100级/赛季 | 赛季时长(60-90天) | 30-60分钟 |

#### 升级时间曲线公式

```
T(Lv) = T_base × Lv^α
```

| 参数 | 定义 | 推荐范围 |
|------|------|---------|
| `T(Lv)` | 从Lv级升到Lv+1级所需时间（分钟） | 计算结果 |
| `T_base` | 基础升级时间（1级→2级的时间） | 5-15分钟 |
| `α` | 增长指数 | 1.3-1.8 |

**不同 α 值的升级体验对比**（T_base = 10分钟）：

| 等级 | α=1.3 | α=1.5 | α=1.8 | 体验感受 |
|------|-------|-------|-------|---------|
| Lv.1→2 | 10分钟 | 10分钟 | 10分钟 | 秒升 |
| Lv.10→11 | 200分钟 | 316分钟 | 631分钟 | 需要认真玩几天 |
| Lv.30→31 | 854分钟 | 1,643分钟 | 4,656分钟 | 需要一周+ |
| Lv.50→51 | 1,778分钟 | 3,536分钟 | 12,589分钟 | 需要数周 |
| Lv.100→101 | 4,786分钟 | 10,000分钟 | 39,811分钟 | 数月磨练 |

**推荐 α 值**：
- 轻度游戏：α = 1.3-1.4（曲线平缓，不劝退）
- 中度游戏：α = 1.5-1.6（标准体验）
- 重度游戏：α = 1.6-1.8（长线留存导向）

#### 等级属性成长模式

| 成长模式 | 公式 | 特点 | 适用场景 |
|---------|------|------|---------|
| 线性成长 | Stat(Lv) = Base + k × Lv | 每级固定成长值 | 简单直观，适合轻度游戏 |
| 百分比成长 | Stat(Lv) = Base × (1+r)^Lv | 指数增长 | 重度RPG，后期数值膨胀大 |
| 分段线性 | 不同阶段不同斜率 | 可精确控制各阶段体验 | 精品RPG |
| 对数成长 | Stat(Lv) = Base + k × ln(Lv) | 前快后慢 | PVP游戏（缩小差距） |

### 5.3 技能树/天赋系统

#### 核心参数设计

| 参数 | 推荐范围 | 设计考量 |
|------|---------|---------|
| 天赋点总量 | 40-80点 | 满级时获得，不够点满所有天赋的60%-80% |
| 技能层级 | 5-7层 | 每层代表一个"能力质变" |
| 每层解锁投入 | 前层投入5-8点 | 制造"差N点解锁下一层"的驱动力 |
| 满级时可点亮 | 总天赋的60%-80% | 迫使选择→差异化→社交讨论 |
| 每个天赋节点价值 | 总战力的0.5%-2% | 单点不能太强（否则路线固化） |
| 关键天赋（终极技能） | 总战力的5%-10% | 每条路线的"毕业技能" |

#### 重置成本设计

| 重置次序 | 成本 | 设计意图 |
|---------|------|---------|
| 第1次 | 免费 | 鼓励试错，降低新手焦虑 |
| 第2-3次 | 低成本（软通货） | 允许合理调整 |
| 第4-5次 | 中成本（软通货×3-5） | 开始感受到成本 |
| 第6次+ | 高成本（硬通货或特殊道具） | 频繁重置成为付费点 |
| 赛季重置 | 免费 | 每赛季重新选择 |

### 5.4 角色养成（Gacha 游戏）

#### 突破/进阶材料需求模型

```
材料需求(等级N) = 基础需求 × 增长率^(N-1)
```

| 突破等级 | 增长倍率 | 累计材料（相对值） | 占总需求比例 |
|---------|---------|-----------------|------------|
| 1→2 | 1.0× | 1 | 2% |
| 2→3 | 1.8× | 2.8 | 5% |
| 3→4 | 2.2× | 6.2 | 10% |
| 4→5 | 2.5× | 15.5 | 24% |
| 5→6 | 2.0× | 31 | 48% |
| 总计 | — | ~56 | 100% |

**关键设计点**：最后一次突破消耗约等于前面所有突破之和。这意味着：
- 将角色养到"能用"（突破4）只需要 ~24% 的总资源
- 将角色养到"满配"（突破6）需要额外 ~76% 的资源
- 这个比例制造了"深度玩家vs普通玩家"的自然分层

#### 多角色养成资源分散策略

| 养成阶段 | 角色数量 | 时间投入 | 资源效率 |
|---------|---------|---------|---------|
| 新手期 | 1-2个主力 | 第1-2周 | 100%集中 |
| 核心队成型 | 4个核心队 | 第3-8周 | 75%核心+25%探索 |
| 扩展期 | 8-12个可用角色 | 第2-6月 | 50%深耕+50%扩展 |
| 收藏期 | 15+角色 | 6月+ | 分散养成 |

**单角色养满时间**：
- 等级满级：2-4周（每日活跃为基准）
- 技能满级：2-3周（限制材料获取频率）
- 装备毕业：4-8周（含刷词条/洗练）
- 总计完全毕业：约 **2-3个月**

## 六、体力/行动力系统设计

体力系统是F2P游戏中最精妙的行为控制机制——它表面上是"限制"，实际上是多种成瘾机制的组合体：制造稀缺感、建立每日登录习惯、创造付费需求、控制内容消耗速度。

### 6.1 基本参数

| 参数 | 推荐范围 | 设计依据 |
|------|---------|---------|
| **体力上限** | 100-200点 | 储存8-16小时的自然回复量 |
| **恢复速率** | 5-10分钟/点 | 8-16小时完全恢复 |
| **完全恢复时间** | 8-16小时 | 覆盖玩家的睡眠时间 |
| **单次游玩消耗** | 总体力的5%-15% | 10-20次游玩消耗完 |
| **日均自然恢复** | 144-288点 | 24小时 ÷ 恢复速率 |

#### 体力系统参数示例（以上限120点、6分钟/点为例）

| 时间节点 | 体力状态 | 玩家行为预期 |
|---------|---------|------------|
| 起床(8:00) | 120/120（满） | 赶紧上线别浪费！ |
| 早通勤(8:30) | 消耗到40/120 | 花15分钟清日常 |
| 午休(12:00) | 75/120（回复了35点） | 再打几关 |
| 午休结束(12:30) | 30/120 | 体力不够了，等下午 |
| 下班(18:00) | 85/120 | 又能打一轮了 |
| 睡前(22:00) | 50/120 | 把体力清空再睡 |
| 次日起床 | 120/120 | 循环 |

#### 溢出机制设计

| 溢出策略 | 效果 | 适用场景 |
|---------|------|---------|
| **硬上限（不可溢出）** | 超过上限停止恢复 | 制造"不浪费"压力（最常用） |
| **软上限（可溢出至150%）** | 超过上限但不再自然恢复 | 通过邮件/任务给予额外体力 |
| **无限制存储** | 自然恢复始终进行 | 休闲游戏/弱FOMO设计 |

**推荐方案**：硬上限 + 邮件体力（可突破上限但不恢复）。这样既保持了"不浪费"的日常压力，又为付费/活动体力提供了溢出空间。

### 6.2 体力消耗设计

#### 关卡体力消耗表

| 关卡类型 | 体力消耗 | 日均可挑战次数 | 奖励价值(SDI) |
|---------|---------|-------------|-------------|
| 日常关卡（普通） | 6-8点 | 15-20次 | 0.03-0.05 |
| 日常关卡（困难） | 10-12点 | 10-12次 | 0.06-0.10 |
| 材料副本 | 15-20点 | 6-8次 | 0.08-0.15 |
| 经验副本 | 15-20点 | 6-8次 | 0.08-0.15 |
| Boss副本 | 20-30点 | 4-6次 | 0.15-0.25 |
| 高难副本 | 30-40点 | 3-4次 | 0.20-0.35 |
| 活动关卡 | 10-20点 | 6-12次 | 0.05-0.15 |

#### 付费补充体力设计

| 购买次序 | 价格(钻石) | 获得体力 | 性价比(体力/钻石) | 设计意图 |
|---------|-----------|---------|-----------------|---------|
| 第1次 | 50 | 60 | 1.20 | 低门槛，高性价比 |
| 第2次 | 100 | 60 | 0.60 | 中等付费 |
| 第3次 | 150 | 60 | 0.40 | 进阶付费 |
| 第4次 | 200 | 60 | 0.30 | 重度付费 |

**价格递增逻辑**：前1-2次购买是"甜蜜点"，大部分月卡/小R玩家会购买；后3-5次的性价比急剧下降，只有大R/鲸鱼玩家会触达。这形成了自然的**价格歧视**机制。

#### 月卡与体力的关系

| 付费档位 | 日额外体力 | 总日体力 | 比免费多 | 月费用 |
|---------|-----------|---------|---------|--------|
| 免费玩家 | 0 | ~180 | — | 0元 |
| 小月卡 | 60 | ~240 | +33% | 30元 |
| 大月卡 | 120 | ~300 | +67% | 68元 |
| 月卡+首次购买 | 120+60 | ~360 | +100% | 68+等价钻石 |

### 6.3 体力系统的本质——行为控制引擎

体力系统绝不仅仅是"限制游玩时间"这么简单。它是一个精密的**行为控制引擎**，同时服务于多个成瘾机制：

#### ① 控制日游玩时长

```
目标日游玩时长 = 体力总量 / 每关消耗体力 × 每关平均时长
```

- 休闲游戏目标：20-30分钟/日
- 中度游戏目标：30-60分钟/日
- 重度游戏目标：60-90分钟/日

体力系统确保所有玩家（包括硬核玩家）的日游玩时长收敛到设计目标范围内，防止"一天刷完所有内容"。

#### ② 制造"每日登录"行为习惯

- 体力溢出 = 浪费 → 玩家产生"不登录就亏了"的FOMO
- 每日固定时间清体力 → **习惯养成**（21天形成习惯，66天形成稳固习惯）
- 体力恢复时间设计为8-16小时 → 自然地创造出"早上清一波、晚上清一波"的两段式登录模式

#### ③ 创造付费需求

- 免费体力"差一点点"不够完成所有日常 → 月卡刚好补齐
- 活动期间奖励丰厚但体力不足 → 体力购买需求上升
- 限时Boss/限时副本 → "这波不买体力就错过了"

#### ④ 控制内容消耗速度

- 新版本的内容量设计为：以正常体力消耗速度需要 **3-4 周** 才能体验完
- 即使买满体力也需要 **1.5-2 周**
- 这确保了版本间隔期间始终有"目标可追"

#### ⑤ 数据分析入口

体力消耗数据是用户行为分析的"金矿"：
- 哪些关卡消耗了最多体力 → 最受欢迎的内容
- 体力购买时间分布 → 用户活跃高峰期
- 体力剩余量分布 → 内容是否过多/过少

## 七、赛季/版本更新数值规划

长线运营游戏的核心挑战在于：如何在持续推出新内容的同时，不让"数值膨胀"失控、不让老玩家感到被背叛、不让新玩家感到追赶无望。

### 7.1 数值膨胀控制

#### 赛季战力膨胀率模型

| 指标 | 健康范围 | 预警线 | 危险线 |
|------|---------|--------|--------|
| 单赛季战力膨胀率 | 15%-30% | 30%-50% | >50% |
| 年度战力膨胀率 | 80%-200% | 200%-300% | >300% |
| 新版本vs上版本DPS差 | 10%-20% | 20%-35% | >35% |
| 新版本vs上版本HP差 | 15%-25% | 25%-40% | >40% |

**膨胀率计算**：

```
赛季膨胀率 = (本赛季顶配战力 - 上赛季顶配战力) / 上赛季顶配战力 × 100%
年度膨胀率 = (1 + 赛季膨胀率)^赛季数 - 1
```

**示例**：若每赛季膨胀20%，每年4个赛季：
```
年度膨胀率 = 1.20^4 - 1 = 107%（翻倍多一点）
```

两年后：`1.20^8 - 1 = 330%`（战力是初始的4.3倍）

#### 追赶机制（Catch-up Mechanism）

每个新赛季开始时，必须为新/回归玩家提供快速追赶路径：

| 追赶方式 | 效率 | 实施方法 |
|---------|------|---------|
| 赛季通行证奖励 | ★★★★★ | 包含上赛季80%战力的装备/材料 |
| 经验/升级加速 | ★★★★ | 老版本经验需求降低50%-70% |
| 跳关/跳级系统 | ★★★★ | 新账号可直接跳到当前赛季起始点 |
| 免费赠送角色/装备 | ★★★ | 赠送上赛季中等水平的角色 |
| 新手保护期 | ★★★ | 前7-14天额外资源产出 |
| 师徒系统 | ★★ | 老玩家带新玩家加速成长 |

**追赶目标**：新玩家在 **2-4 周** 内应能达到上赛季 **80%** 的战力水平，在 **4-6 周** 内可以参与当赛季的核心内容。

### 7.2 新内容数值定位

#### 新角色/装备的战力定位

```
新角色推荐战力 = 上赛季巅峰战力 × 1.10 ~ 1.20
```

| 定位策略 | 描述 | 优点 | 风险 |
|---------|------|------|------|
| 数值压制型 | 纯属性碾压上版本角色 | 短期收入高 | 老角色迅速贬值，玩家愤怒 |
| 机制创新型 | 数值持平但有新机制 | 长线健康 | 短期收入可能不如数值型 |
| **混合型（推荐）** | 10%-15%数值提升 + 新机制 | 平衡收入与体验 | 需要精心设计 |
| 侧面提升型 | 特定场景/队伍极强 | 丰富生态 | 通用性不足可能卖不动 |

**避免"数值螺旋"（Power Creep Death Spiral）**：

当新角色的优势 **100% 来自数值碾压** 时，会陷入以下死循环：
1. 新角色数值强 → 玩家抽取
2. 老角色贬值 → 玩家对投入的沉没成本愤怒
3. 下一个角色必须更强才能卖出 → 膨胀加速
4. 重复 2-3 → 直到数值体系崩坏

**解法**：每个新角色的优势应该是 **30%-50% 来自数值、50%-70% 来自机制独特性**。

#### 平衡更新节奏

| 更新类型 | 频率 | 内容 |
|---------|------|------|
| 热修复（Hotfix） | 需要时立即 | 修复严重Bug/数值错误 |
| 微调（Tuning） | 每2-4周 | 小幅数值调整（±5%-10%） |
| 平衡大改 | 每2-3个月 | 重大机制/数值调整（±15%-30%） |
| 赛季重置 | 每3-4个月 | 全局重新校准 |

### 7.3 实用数值设计模板——Excel 工作簿结构

以下是一个完整的数值设计 Excel 工作簿的推荐结构，涵盖数值策划日常工作中最核心的五张表：

#### Sheet 1：资源产出消耗表

| 列 | 内容 | 说明 |
|----|------|------|
| A | 资源名称 | 金币、钻石、经验、体力等 |
| B | 获取途径 | 任务、关卡、活动、商城、付费 |
| C | 日产量（免费） | 免费玩家每日获取量 |
| D | 日产量（月卡） | 月卡用户每日获取量 |
| E | 日产量（大R） | 重度付费用户每日获取量 |
| F | 日消耗（推荐） | 设计推荐的日均消耗量 |
| G | 产出/消耗比 | =C/F（应在0.8-1.2之间） |
| H | 周存量变化 | =(C-F)×7 |
| I | 月通胀率 | =H×4/玩家中位数存量 |
| J | 预警标识 | 条件格式：I>5%标红 |

#### Sheet 2：升级曲线表

| 列 | 内容 | 说明 |
|----|------|------|
| A | 等级 | 1到满级 |
| B | 升级所需经验 | =T_base × A^alpha |
| C | 累计总经验 | =SUM(B$2:B2) |
| D | 升级所需时间(分钟) | =B/每分钟经验获取量 |
| E | 累计时间(小时) | =SUM(D$2:D2)/60 |
| F | 累计时间(天) | =E/日均游玩时长 |
| G | 各级属性值(HP) | =Base_HP × (1+growth)^A 或分段函数 |
| H | 各级属性值(ATK) | =Base_ATK × (1+growth)^A |
| I | 战力估算 | =G×w1 + H×w2 + ... |

#### Sheet 3：装备强化概率表

## 结语

数值策划是一门"看似理性、实则感性"的技艺。所有的公式和参数都只是工具，最终目标是**让玩家在每一个时刻都感到"值得继续"**。

好的数值设计有三个检验标准：

1. **即时反馈**：玩家的每一次操作都应在30秒内获得可感知的正反馈
2. **持续进步**：玩家每天登录都应能感知到自己比昨天更强
3. **永恒目标**：无论玩家处于什么阶段，都应有一个"可望但尚不可及"的目标在前方

当这三条标准同时满足时，成瘾循环就自然形成了。

> **免责声明**：本手册旨在提供数值设计的技术参考。游戏设计者应在追求商业目标的同时，关注玩家的心理健康，遵守相关法规（如概率公示、未成年人保护），在"好玩"和"负责任"之间找到平衡。
