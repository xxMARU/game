### 1.2 阅读路径建议

不同岗位的最优阅读顺序如下，按箭头方向依次深入：

**🎯 新手策划（系统策划入门）**
```

```
> 先建立心理学直觉，再了解机制分类，学习行为设计方法，最后对照实际案例加深理解。

```
01 心理学基础 → 02 机制分类（重点看数值阈值） → 05 数值手册 → 04 留存付费
```

```
04 留存付费 → 06 行为钩子 → 03 品类案例
```
> 从最贴近 KPI 的留存/付费方法论入手，学习行为驱动工具，案例库提供参考基准。


> 宏观理论 → 市场验证 → 商业模型 → 总控检查清单，形成全局视野。

```
01 心理学基础 → 02 机制分类 → 05 数值手册 → 06 行为钩子
```

> 独立开发者需要从理论到落地全链路一人搞定，按此顺序效率最高。

## 二、成瘾机制设计检查清单

> 以下检查清单按项目阶段组织，每个阶段对应一组 checkbox。建议在 Notion / 飞书等工具中导入使用，逐项打钩确认。

### 2.1 项目启动阶段检查清单

**目标**：确定项目方向、核心机制选型与商业化框架。

- [ ] 确定核心品类与目标用户画像（年龄/性别/地域/付费意愿）
- [ ] 完成竞品分析报告（至少 3-5 款同品类头部产品）
- [ ] 选定 2-3 个主成瘾驱动机制（参考文档 02 六大分类）
- [ ] 定义核心游戏循环（Core Loop）：输入 → 挑战 → 奖励 → 成长
- [ ] 设定留存目标值（参考文档 03/04）：
  - D1 留存目标：_____%
  - D7 留存目标：_____%
  - D30 留存目标：_____%
- [ ] 设定付费模型（免费制 / 买断制 / 订阅制 / 混合制）
- [ ] 确定 LTV 目标与付费率预期
  - 目标付费率：_____%
  - 目标 ARPPU：$_____
  - 目标 LTV（D180）：$_____
- [ ] 规划成长曲线并设定关键里程碑（参考文档 05 第四章）
- [ ] 设计初版经济系统框架：水龙头/水池/排水口三端建模（参考文档 05 第三章）
- [ ] 确定内容更新路线图（至少规划上线后 6 个月）
- [ ] 确定数据埋点方案与核心指标看板

### 2.2 新手体验设计检查清单

**目标**：确保新玩家在首次体验中被有效"钩住"，最大化 D1 留存。

**首次体验时间线：**

- [ ] 前 **30 秒**是否有第一次正反馈？（视觉/听觉/操作反馈）
- [ ] 前 **3 分钟**是否完成第一个核心循环（Core Loop）？
- [ ] 前 **10 分钟**是否触达 Aha Moment（顿悟时刻）？
- [ ] 前 **30 分钟**是否解锁至少 3 个系统功能？
- [ ] 首次游戏结束前是否有明确的"下次再来"理由？

**新手引导质量：**

- [ ] 新手引导步骤总数是否 ≤ 20 步？
- [ ] 每步操作是否 ≤ 3 个动作（点击/滑动/选择）？
- [ ] 是否采用"做中学"（Learning by Doing）而非纯文字教程？
- [ ] 渐进式解锁节奏是否每 3-5 分钟解锁 1 个新功能？
- [ ] 是否有跳过选项（面向老玩家/回流玩家）？

**首日留存钩子：**

- [ ] 首日是否建立至少 1 个**未完成任务**（蔡格尼克效应）？
- [ ] 首日是否给予限时奖励预告（"明天登录领取 XXX"）？
- [ ] 首日推送策略是否设置？（离开后 2h / 6h / 24h 三波触发）
- [ ] 首日是否引导加入社交关系（好友/公会/世界频道）？

**性能与体验：**

- [ ] 首次加载时间是否 < 3 秒（冷启动）？
- [ ] 新手引导跳过率监控是否设置？（预警阈值 > 30%）
- [ ] 新手引导完成率是否 ≥ 85%？
- [ ] 是否有新手保护期（PVP 免战 / 资源保护 / 降低难度）？

### 2.3 奖励系统设计检查清单

**目标**：构建分层、多频次、可变的奖励体系，维持持续的多巴胺刺激。

**奖励分层设计（参考文档 02/05）：**

- [ ] 是否定义了完整的 6 级奖励分层？
  - 微型奖励（金币/经验/碎片）：频率 10-30 秒
  - 小型奖励（装备/道具/宝箱）：频率 3-5 分钟
  - 中型奖励（稀有道具/角色碎片）：频率 15-30 分钟
  - 大型奖励（SSR 角色/传说装备）：频率 1-3 天
  - 里程碑奖励（赛季奖励/成就奖励）：频率 1-4 周
  - 终极奖励（限定/绝版收藏）：频率 1-3 个月
- [ ] 微型奖励间隔是否在 **10-30 秒**？
- [ ] 每次会话（20-45 分钟）是否包含足够奖励密度（至少 8-15 次奖励反馈）？

**变比率强化设计（参考文档 01/02）：**

- [ ] 变比率奖励比率是否在 **1:3 到 1:8** 区间？
- [ ] 是否混合使用固定比率与变比率？（建议 40:60）
- [ ] 是否有"热手效应"设计（连续好运概率微调）？

**抽卡/Gacha 设计（参考文档 02/05）：**

- [ ] 抽卡概率是否设计了保底机制（Pity System）？
- [ ] 软保底触发点是否设置？（通常为硬保底的 60-75%）
- [ ] 连续无奖励次数是否控制在 **15 次以内**？
- [ ] 概率是否依法公示？（中国/日本/韩国/欧盟各有要求）

**经济平衡（参考文档 05）：**

- [ ] 奖励类型轮换周期是否在 **7-14 天**？
- [ ] 经济通胀率是否控制在月 **3-5%** 以内？
- [ ] 资源回收机制（Sink）是否完善？（强化/合成/消耗/交易税/赛季重置）
- [ ] 免费玩家是否能获得足够的游戏体验？（付费加速但不锁内容）

### 2.4 留存机制设计检查清单

**目标**：构建从 D1 到 D365 的全生命周期留存体系。

**日常留存（D1-D7 短期留存）：**

- [ ] 每日签到系统是否设计？（7 天循环 + 累积签到双轨制）
- [ ] 签到第 7 天是否有显著大奖？（价值 ≥ 第 1-6 天总和）
- [ ] 每日任务系统是否 5-8 个任务、总计 15-30 分钟？
- [ ] 活跃度积分系统是否有 4 个奖励档位？（30/60/90/120 分）
- [ ] 每日限时活动是否有固定时间段？（午休 12:00-14:00 / 晚间 20:00-22:00）

**中期留存（D7-D30）：**

- [ ] D1-D3 是否有社交绑定引导？（加好友/加公会/师徒系统）
- [ ] D3-D7 是否核心功能全部解锁？（PVP/公会/装备系统/副本）
- [ ] D7-D14 是否有新功能/玩法持续解锁？（挑战模式/排位赛/世界Boss）
- [ ] D14-D30 是否有赛季/活动目标牵引？
- [ ] 周循环活动是否设计完善？（周一至周日各有特色活动）

**长期留存（D30+）：**

- [ ] 回流机制是否设计？（回归签到 + 追赶机制 + 回归专属活动）
- [ ] 终局内容（End-Game）是否充实？
  - PVP 排位/段位系统
  - 赛季排行与奖励
  - 高难挑战关卡
  - 收集完成度系统
  - 社交/公会深度内容
- [ ] 内容更新节奏是否规划？
  - 小更新（活动/平衡调整）：每 1-2 周
  - 中更新（新角色/新关卡/新系统）：每 4-6 周
  - 大更新（新资料片/新赛季/新玩法）：每 3-6 个月
- [ ] 赛季系统是否设计？（赛季时长 60-90 天为佳）


### 2.5 付费系统设计检查清单

**目标**：构建健康、可持续、高转化的付费体系。

**首充与入门付费：**

- [ ] 首充礼包是否设计？（$0.99-$2.99，呈现 5-10 倍价值感）
- [ ] 首充触发时机是否合理？（建议在 D1 Aha Moment 后触发）
- [ ] 首充礼包是否有"仅此一次"的限时标签？
- [ ] 新手特惠礼包是否设计？（逐级解锁 3-5 个，价格递增）

**订阅与通行证：**

- [ ] 月卡系统是否设计？（$4.99-$9.99，每日领取，分 30 天发放）
- [ ] 月卡价值是否为直接购买的 3-5 倍？
- [ ] Battle Pass 是否设计？（$9.99-$14.99 / 赛季）
- [ ] Battle Pass 等级数是否 50-100 级？
- [ ] 免费层奖励是否占总价值 **30-40%**？（过低则免费玩家流失，过高则付费动力不足）
- [ ] Battle Pass 最后 10% 等级是否有专属炫耀奖励？

**价格策略：**

- [ ] 价格锚定是否正确设置？（高价商品旁放中价商品，提升中价转化）
- [ ] 钻石/代币包是否有 5-6 档？（$0.99 / $4.99 / $9.99 / $24.99 / $49.99 / $99.99）
- [ ] 高档位是否有明显的"额外赠送"标签？（赠送比例随档位递增）
- [ ] 折扣幅度是否在 **30-70%** 区间？（< 30% 吸引力不足，> 70% 贬值品牌）
- [ ] 限时折扣频率是否合理？（每月 2-3 次大促，避免折扣疲劳）

**付费体验与合规：**

- [ ] 每月付费弹窗/提醒是否 ≤ 5 次？（过多引发反感）
- [ ] 概率是否依法公示？（中国：文化部规定；日本：JOGA 指南；欧盟：数字服务法案）
- [ ] 是否设置了单日/单月充值上限？
- [ ] 消费达到阈值时是否有提醒弹窗？（如单日 > $50 / 单月 > $200）
- [ ] 未成年人付费限制是否符合各市场法规？
- [ ] 退款流程是否清晰？

### 2.6 社交系统设计检查清单

**目标**：通过社交关系构建高转换成本的留存护城河。

**公会/帮派系统：**

- [ ] 公会系统是否支持 **20-50 人**活跃运转？
- [ ] 公会等级系统是否有 10-20 级成长空间？
- [ ] 每日是否有公会任务？（贡献值/公会币奖励）
- [ ] 每周是否有公会战/公会副本？
- [ ] 公会内是否有职位/权限系统？（会长/副会长/长老/成员）
- [ ] 公会聊天是否活跃？是否有公会公告/邮件系统？

**好友与社交互动：**

- [ ] 好友系统上限是否 **100-200 人**？
- [ ] 是否有好友亲密度系统？（互动加分，解锁特殊奖励）
- [ ] 社交赠礼系统是否设计？（每日互赠体力/道具）
- [ ] 协作内容（组队/协作任务/公会活动）占总内容比是否 **30-40%**？
- [ ] 师徒系统是否设计？（老带新，双向奖励）

**竞争与展示：**

- [ ] 排行榜是否分层？
  - 全服排行榜（Top 100/500）
  - 区服/赛区排行榜
  - 好友圈排行榜
  - 公会内排行榜
- [ ] 排行榜是否每周/赛季重置？（避免固化，给新玩家希望）
- [ ] 社交展示系统是否完善？
  - 头像框 / 称号系统
  - 皮肤 / 时装展示
  - 个人主页 / 战绩展示
  - 成就勋章系统
- [ ] 社交分享功能是否设计？（截图/录屏/一键分享到社交平台）

### 2.7 数值平衡检查清单

**目标**：确保游戏难度处于心流通道，PVE/PVP 体验公平且有趣。

**心流与难度（参考文档 01/05）：**

- [ ] 心流通道是否维持？（挑战难度与玩家技能差距 ≤ **±15%**）
- [ ] DDA（动态难度调整）系统是否设计？
  - 连续失败 **3 次以上** → 降低难度 5-10%
  - 连续成功 **5 次以上** → 提升难度 5-10%
  - 调整幅度上限 ±20%，避免玩家感知
- [ ] Boss 战斗时长是否合理？
  - 普通 Boss：2-5 分钟
  - 精英 Boss：5-10 分钟
  - Raid Boss：10-20 分钟
- [ ] 通关率是否符合目标？
  - 简单难度：**90%+**
  - 普通难度：**70-85%**
  - 困难难度：**40-60%**
  - 极难/挑战：**10-25%**

**PVP 平衡：**

- [ ] PVP 匹配胜率是否维持 **45-55%**？（长期 50% 趋近）
- [ ] 匹配等待时间是否 < 30 秒（休闲）/ < 60 秒（竞技）？
- [ ] ELO/MMR 分段是否合理？（建议 6-8 个大段，每段 3-5 小段）
- [ ] 新赛季段位重置是否合理？（回退 2-3 个小段，而非从零开始）

**数值膨胀控制：**

- [ ] 赛季战力膨胀是否控制在 **15-30%/赛季**？
- [ ] 追赶机制是否提供上赛季 **80%** 战力快速路径？
- [ ] 数值压缩（Stat Squish）计划是否在路线图中？（每 3-4 个大版本一次）
- [ ] 新角色/装备是否经过平衡测试？（内测 → 封闭测试 → 公测三阶段验证）

### 2.8 行为钩子检查清单

**目标**：用 Hook 模型构建玩家行为习惯，最大化日活和会话频次。

**Hook 四阶段完整性（参考文档 06）：**

- [ ] **触发（Trigger）**阶段是否设计？
  - 外部触发：推送通知 / 邮件 / 社交邀请 / 广告再营销
  - 内部触发：无聊 → 打开游戏 / 焦虑 → 检查进度 / 社交需求 → 公会互动
- [ ] **行动（Action）**阶段是否设计？
  - 行动成本是否最小化？（一键扫荡 / 快速匹配 / 自动战斗 / 断点续玩）
  - 从推送到进入游戏是否 < 5 秒？
- [ ] **可变奖励（Variable Reward）**阶段是否设计？
  - 猎物奖励（The Hunt）：随机掉落 / 抽卡
  - 部落奖励（The Tribe）：社交认可 / 排名上升
  - 自我奖励（The Self）：成就感 / 技能提升
- [ ] **投入（Investment）**阶段是否设计？
  - 时间投入：升级 / 培养 / 收集进度
  - 社交投入：好友 / 公会关系
  - 金钱投入：付费记录
  - 数据投入：个性化设置 / 存储价值

**推送与触发管理：**

- [ ] 推送频率是否 ≤ **3 条/日**？
- [ ] 推送打开率是否监控？（行业基准 **5-15%**，预警阈值 < 3%）
- [ ] 推送内容是否个性化？（基于玩家行为 / 进度 / 偏好）
- [ ] 是否有推送偏好设置？（允许玩家选择接收类型和频率）
- [ ] 沉默用户推送策略是否差异化？（3 天/7 天/14 天/30 天不同话术）

**日常循环设计：**

- [ ] 每日循环时长是否 **30-45 分钟**（核心内容）？
- [ ] 是否有弹性时间设计？（核心 30 分钟 + 可选 60 分钟深度内容）
- [ ] 限时活动是否有倒计时设计？（制造紧迫感）
- [ ] FOMO 强度分布是否合理？
  - 安全区（温和提醒，无实质损失）：**60%**
  - 中度区（错过有一定损失但可弥补）：**30%**
  - 极端区（错过不可逆，如限定皮肤）：**10%**
- [ ] 习惯形成指标是否监控？
  - 连续登录天数分布
  - 日均会话次数
  - 固定时段登录率（是否形成时间锚点）

### 2.9 合规与伦理检查清单

**目标**：确保设计合法合规，避免伦理和法律风险。

**未成年人保护：**

- [ ] 未成年人防沉迷系统是否合规？
  - 中国：实名认证 + 每日/周/月游戏时长限制 + 充值限额
  - 韩国：深夜禁令（Shutdown Law，虽已废除但需了解历史政策）
  - 其他市场：按当地法规执行
- [ ] 年龄门控是否设置？（注册时年龄确认 + 实名验证）
- [ ] 未成年人付费上限是否设置？

**概率与付费透明度：**

- [ ] 概率是否公示？（中国文化部要求、日本 JOGA 自律规范、Apple/Google 商店政策）
- [ ] 保底机制是否明确告知玩家？
- [ ] 是否有充值上限？（建议设置，即使法规未强制）
- [ ] 是否有消费提醒？（单日/单月消费达阈值时弹窗提醒）
- [ ] 概率是否真实？（服务器端验证，避免暗改概率的法律风险）

**伦理设计底线：**

- [ ] 是否避免了**掠夺性设计**？（针对冲动消费者的高压推送、深夜弹窗折扣等）
- [ ] 是否避免了**黑暗模式**？（故意混淆的 UI 设计、隐藏取消按钮等）
- [ ] 是否尊重玩家时间？（避免无意义的重复刷任务）
- [ ] 是否有健康游戏提醒？（连续游戏 1h/2h/3h 提示休息）
- [ ] 各目标市场法规是否逐一核查？（中国/日本/韩国/美国/欧盟/东南亚）

## 四、设计流程模板

### 4.1 成瘾机制设计工作流

以下为从立项到上线运营的完整成瘾机制设计工作流，共 8 个阶段：

```
┌─────────────────────────────────────────────────────────────────┐
│  Step 1    Step 2    Step 3    Step 4    Step 5    Step 6    Step 7    Step 8  │
│  市场分析  心理学    核心机制  数值框架  留存模型  行为钩子  原型测试  数据迭代 │
│  ───────►  ───────►  ───────►  ───────►  ───────►  ───────►  ───────►  ──────  │
│  [Doc 03]  [Doc 01]  [Doc 02]  [Doc 05]  [Doc 04]  [Doc 06]  [A/B]    [持续]  │
└─────────────────────────────────────────────────────────────────┘
```

**Step 1：市场分析与品类选择（参考文档 03）**
- 分析目标市场规模与竞争格局
- 选定品类方向（RPG/MOBA/SLG/休闲/二次元等）
- 完成 3-5 款竞品深度拆解（核心循环/付费/留存数据）
- 确定差异化定位与目标用户画像

**Step 2：心理学模型选择（参考文档 01）**
- 从 7 大心理学理论中选择 2-3 个核心驱动理论
- 明确玩家动机模型（成就/社交/探索/竞争）
- 定义目标情绪曲线（兴奋→紧张→成就→放松→期待）

**Step 3：核心机制选择（参考文档 02）**
- 从 6 大机制分类中选择主/辅机制组合
- 设计核心循环（Core Loop）并验证可行性
- 定义机制间的协同关系

**Step 4：数值框架设计（参考文档 05）**
- 建立经济系统模型（水龙头/水池/排水口）
- 设计成长曲线与里程碑
- 建立概率模型（抽卡/掉落/强化）
- 设定难度曲线与心流参数

**Step 5：留存模型设计（参考文档 04）**
- 设计全生命周期留存漏斗
- 规划各时间节点留存策略（D1/D3/D7/D14/D30/D90）
- 设计付费转化路径与价格体系
- 建立 LTV 预测模型

**Step 6：行为钩子设计（参考文档 06）**
- 设计 Hook 模型四阶段
- 规划日活循环与每周节奏
- 设计推送策略与触发时机
- 规划习惯养成节点（7天/21天/66天）

**Step 7：原型测试与 A/B 测试**
- 核心循环可玩性测试（纸面原型 → 数字原型）
- 新手体验测试（目标：D1 留存 ≥ 基准线）
- A/B 测试关键变量（奖励频率/难度/推送文案/价格）
- 封闭测试 → 小规模公测 → 数据收集

**Step 8：数据驱动迭代（持续进行）**
- 建立核心指标看板（DAU/留存/付费/LTV/会话数据）
- 每周数据周报 + 每月深度复盘
- 基于数据调优：奖励频率、难度曲线、价格、活动节奏
- A/B 测试持续运行，小步快跑迭代

### 4.2 每月运营检查清单

以下为标准化的月度运营节奏模板：
