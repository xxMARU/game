# 核心循环设计方法论

> 本文档系统梳理核心循环（Core Loop）的理论基础、设计方法、诊断工具与商业化策略，覆盖从独立游戏到大型活服产品的全谱系实践。

---

## 第一章 理论框架

### 1.1 Core Loop 标准定义

**Daniel Cook 的"游戏设计化学"（The Chemistry of Game Design, 2007）** 是核心循环理论的奠基文献。Cook 将游戏体验类比为化学反应，提出了"技能原子"（Skill Atom）模型：

```
玩家行动（Action）→ 模拟规则（Simulation）→ 反馈信号（Feedback）→ 心智模型更新（Mental Model Update）→ 再行动
```

**核心定义：**
核心循环是游戏中**最小的、可自洽的、可持续产生乐趣的交互闭环**。它满足以下条件：

1. **可重复性（Repeatable）**：玩家可以无限次执行该循环而不产生内容枯竭。
2. **内在激励（Intrinsically Motivating）**：即使剥离外部奖励，循环本身的操作依然令人愉悦。
3. **技能敏感（Skill-Sensitive）**：玩家的表现差异可在循环结果中体现。
4. **状态推进（State Progression）**：每次循环结束后，游戏世界或玩家状态发生有意义的变化。

Cook 将这一概念与学习理论结合，认为游戏的本质是"可实践的学习机器"——每个循环周期就是一次"假设→验证→修正"的微型科学实验。

**经典示例：**

| 游戏 | 核心循环描述 | 循环周期 |
|------|-------------|---------|
| Tetris | 观察方块→旋转/移动→消行 | 2-5秒 |
| Doom(1993) | 移动→瞄准→射击→拾取 | 3-8秒 |
| Civilization | 分配城市生产→移动单位→探索/战斗→回合结算 | 30-120秒 |
| Stardew Valley | 规划日程→执行农活/社交→结算一天 | 5-15分钟 |

### 1.2 MDA 框架与核心循环的关系

**MDA 框架（Mechanics-Dynamics-Aesthetics）** 由 Hunicke、LeBlanc 和 Zubek 于 2004 年在 GDC 提出，是分析游戏设计的经典三层模型：

```
设计者视角：Mechanics → Dynamics → Aesthetics
玩家视角：  Aesthetics → Dynamics → Mechanics
```

**三层对应关系：**

| MDA 层 | 定义 | 与核心循环的关系 |
|--------|------|-----------------|
| **Mechanics（机制）** | 游戏规则、数值、系统参数 | 核心循环的**骨架**——定义"玩家能做什么"以及"系统如何响应" |
| **Dynamics（动态）** | 机制在运行时产生的行为模式 | 核心循环的**肌肉**——玩家实际体验到的策略空间和涌现行为 |
| **Aesthetics（美学）** | 玩家感受到的情绪体验 | 核心循环的**灵魂**——最终回答"为什么好玩" |

**关键洞察：**

- **核心循环是 MDA 三层的交汇点**。一个设计精良的核心循环意味着：Mechanics 足够简洁、Dynamics 足够丰富、Aesthetics 足够清晰。
- **从 Mechanics 调参修复 Aesthetics 问题时，核心循环是最优先的检查对象**。如果核心循环本身不有趣，外围系统的包装无法挽救体验。
- **MDA 的八种美学类型**（感官、幻想、叙事、挑战、社交、发现、表达、消遣）可作为核心循环的"目标美学"来指导设计方向。

### 1.3 Compulsion Loop vs Core Loop：关键区别

这两个概念经常被混用，但它们在设计哲学上有本质差异：

| 维度 | Core Loop（核心循环） | Compulsion Loop（强迫循环） |
|------|---------------------|---------------------------|
| **驱动力来源** | 内在激励（好奇、掌控、创造） | 外在激励（奖励预期、损失厌恶） |
| **移除奖励后** | 玩家依然觉得有趣 | 玩家立刻丧失动力 |
| **情绪签名** | 心流（Flow）、成就感、探索欲 | 焦虑、不舍得走、"再刷一把"的空虚感 |
| **设计目标** | 最大化单位时间乐趣密度 | 最大化用户停留时间 |
| **典型手法** | 操作手感优化、策略深度设计 | 变比率强化计划（Variable Ratio Schedule）、FOMO |
| **伦理边界** | 尊重玩家自主性 | 可能滑向"暗黑模式"（Dark Pattern） |
| **经典代表** | Super Mario（操作本身就是乐趣） | 部分手游的"每日签到→抽卡→数值膨胀"链条 |

**实践建议：**

> 健康的游戏设计应以 Core Loop 为主干，Compulsion Loop 作为辅助维持手段。
> 检验标准：**如果将游戏中的所有外部奖励（经验值、货币、掉落）清零，核心操作是否依然令人愉悦？**
> - 如果"是"→ Core Loop 健康。
> - 如果"否"→ 你可能在设计一个 Compulsion Loop 而非 Core Loop。

**灰色地带：**

部分经典设计巧妙地融合了两者。例如 Diablo 系列的 Action RPG 循环：
- Core Loop 层：战斗操作本身具备手感和策略性（技能组合、走位、怪物机制识别）。
- Compulsion Loop 层：随机掉落的装备产生"变比率强化"效应，驱动持续刷怪。
- 两者的结合创造了该品类独特的"上瘾但不空虚"的体验，前提是 Core Loop 足够扎实。

### 1.4 循环层级划分

游戏体验由多层嵌套的循环构成，从毫秒级的微操到跨越数月的赛季目标。以下是标准的七级划分模型：

```
┌─────────────────────────────────────────────────────┐
│  L7 年/生命周期循环（Year/Lifecycle Loop）           │
│  ┌───────────────────────────────────────────────┐  │
│  │  L6 赛季循环（Season Loop）                    │  │
│  │  ┌───────────────────────────────────────────┐│  │
│  │  │  L5 周循环（Weekly Loop）                  ││  │
│  │  │  ┌───────────────────────────────────────┐││  │
│  │  │  │  L4 日循环（Daily Loop）               │││  │
│  │  │  │  ┌─────────────────────────────────┐  │││  │
│  │  │  │  │  L3 时循环（Session Loop）       │  │││  │
│  │  │  │  │  ┌───────────────────────────┐   │  │││  │
│  │  │  │  │  │  L2 分钟循环（Minute Loop）│   │  │││  │
│  │  │  │  │  │  ┌─────────────────────┐  │   │  │││  │
│  │  │  │  │  │  │ L1 秒循环（Core）   │  │   │  │││  │
│  │  │  │  │  │  └─────────────────────┘  │   │  │││  │
│  │  │  │  │  └───────────────────────────┘   │  │││  │
│  │  │  │  └─────────────────────────────────┘  │││  │
│  │  │  └───────────────────────────────────────┘││  │
│  │  └───────────────────────────────────────────┘│  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**各层级定义与功能：**

| 层级 | 名称 | 时间尺度 | 功能 | 游戏举例 |
|------|------|---------|------|---------|
| **L1** | 秒循环（Micro Loop） | 0.1s - 10s | 操作手感、即时反馈 | 一次攻击动作、一次跳跃、放置一个方块 |
| **L2** | 分钟循环（Engagement Loop） | 10s - 5min | 战术决策、小目标完成 | 一场遭遇战、一个谜题、一波怪物清理 |
| **L3** | 时循环（Session Loop） | 5min - 2h | 一次游戏会话的起承转合 | 一局对战、一个关卡、一次地下城探索 |
| **L4** | 日循环（Daily Loop） | 1天 | 每日参与动机、习惯养成 | 每日任务、体力恢复、签到奖励 |
| **L5** | 周循环（Weekly Loop） | 1周 | 中期目标节奏感 | 周挑战、赛季任务推进、工会活动 |
| **L6** | 赛季循环（Season Loop） | 1-3个月 | 大版本内容消耗、Meta 更新 | 赛季通行证、排位赛季、新英雄/地图轮换 |
| **L7** | 年循环（Lifecycle Loop） | 6个月-多年 | 产品级生命周期管理 | 大版本更新、资料片、周年庆典、跨代传承 |

**层级之间的关系法则：**

1. **内层驱动体验，外层驱动留存**：L1-L2 决定"好不好玩"，L4-L7 决定"能不能留住人"。
2. **内层质量不可被外层替代**：再好的赛季设计也无法拯救手感糟糕的战斗系统。
3. **每层循环必须有独立的"完成感"**：即使玩家只玩一个 Session（L3），也应获得完整体验。
4. **外层循环的奖励应反哺内层循环的体验多样性**：例如赛季奖励的新角色应丰富战斗的策略空间，而非仅仅是数值膨胀。

## 第二章 设计方法论

### 2.1 核心循环三要素：行动→反馈→奖励

核心循环的最小结构由三个不可或缺的要素构成：

```
    ┌──────────┐
    │   行动   │ ← 玩家做出的有意义选择或操作
    │ (Action) │
    └────┬─────┘
         │
         ▼
    ┌──────────┐
    │   反馈   │ ← 系统对行动的即时响应信号
    │(Feedback)│
    └────┬─────┘
         │
         ▼
    ┌──────────┐
    │   奖励   │ ← 驱动下一次行动的激励
    │ (Reward) │
    └────┬─────┘
         │
         └──────→ 回到"行动"（循环闭合）
```

**2.1.1 行动（Action）**

行动是玩家向系统的输入。优质行动设计需满足：

| 属性 | 描述 | 反例 |
|------|------|------|
| **有意义的选择** | 行动之间存在权衡（trade-off） | 只有一个"最优解"的伪选择 |
| **可读性** | 玩家能清晰理解"我现在能做什么" | 界面信息过载导致决策瘫痪 |
| **操作成本合理** | 输入复杂度与决策权重匹配 | 每个小操作都需要三次确认弹窗 |
| **频率适中** | 每秒 0.5-3 次有意义操作（因品类而异） | 自动战斗——玩家无需任何输入 |

**2.1.2 反馈（Feedback）**

反馈是系统对玩家行动的回应。反馈设计的核心原则是**"信息丰富、感官愉悦、时机精确"**。

反馈的四个维度：

1. **视觉反馈**：特效、UI 动画、屏幕震动、慢动作（Hitlag）
2. **听觉反馈**：音效层叠（Impact Sound + UI Sound + 环境回响）
3. **触觉反馈**：手柄震动（HD Rumble）、移动端线性马达
4. **信息反馈**：伤害数字、进度条变化、评价等级

**反馈强度应与行动权重成正比：**

| 行动权重 | 反馈强度 | 示例 |
|---------|---------|------|
| 高频微操（每秒多次） | 轻量、清脆 | 《Hades》普通攻击的微振+音效 |
| 中频战术动作（每10-30秒） | 中等、有层次 | 《XCOM》命中时的镜头切换+慢动作 |
| 低频战略决策（每分钟+） | 重量、仪式感 | 《文明》完成奇观时的过场动画 |

**2.1.3 奖励（Reward）**

奖励是闭合循环、驱动下一次行动的引擎。关键在于区分三种奖励类型：

| 类型 | 定义 | 作用 | 风险 |
|------|------|------|------|
| **内在奖励** | 行动本身带来的满足感（掌控感、好奇心满足） | 维持长期动力，不需要内容填充 | 需要极高的基础机制品质 |
| **进度奖励** | 角色成长、解锁、收集进度 | 提供方向感和中期目标 | 过度依赖会导致"数值跑步机"感 |
| **随机奖励** | 随机掉落、抽卡、程序生成内容 | 制造惊喜感和期待感 | 过度使用导致赌博化倾向 |

**黄金配比建议（非硬性规则）：**

- **核心向游戏**（Dark Souls、Hollow Knight）：内在奖励 60% + 进度奖励 30% + 随机奖励 10%
- **内容驱动型**（开放世界、RPG）：内在奖励 30% + 进度奖励 50% + 随机奖励 20%
- **活服运营型**（手游、GaaS）：内在奖励 20% + 进度奖励 40% + 随机奖励 40%

### 2.2 各层级理想时长参数表

以下参数基于行业实践和玩家心理学研究整理，仅作参考基准，需根据品类和目标用户调整：

| 层级 | 理想时长范围 | 最佳甜蜜点 | 设计依据 | 品类差异注释 |
|------|------------|-----------|---------|-------------|
| **L1 秒循环** | 0.1s - 10s | 1-3s | 工作记忆窗口（Miller's Law: 7±2）；超过10秒注意力开始衰减 | FPS/ACT: 0.5-2s; SLG/4X: 5-10s |
| **L2 分钟循环** | 10s - 5min | 30s-2min | 短期目标完成带来的多巴胺脉冲；超过5分钟单一活动会产生疲劳 | MOBA团战: 20-40s; 解谜: 2-5min |
| **L3 时循环** | 5min - 120min | 15-45min | 典型移动端会话: 5-15min; PC/主机会话: 30-90min | 手游: 5-15min; 3A: 30-90min |
| **L4 日循环** | 24h（锁定） | N/A | 生物钟节律同步；每日首次登录的"新鲜感窗口" | 手游日活核心; 买断制可忽略 |
| **L5 周循环** | 5-7天 | 7天 | 社会时间节律；周末=高游戏时间 | 竞技: 周排名重置; MMO: 周副本CD |
| **L6 赛季循环** | 30-90天 | 60-75天 | 内容消耗速度平衡；过短则压力过大，过长则倦怠 | 竞技: 60天; 手游: 30-45天 |
| **L7 年循环** | 6-18个月 | 12个月 | 大版本内容开发周期；周年庆营销节点 | 3A DLC: 6-12月; MMO资料片: 12-18月 |

### 2.3 反馈延迟设计

反馈延迟（Feedback Latency）是指从玩家完成输入到感知到系统回应的时间差。它是核心循环"手感"的决定性因素。

**反馈延迟的层级对照表：**

| 延迟范围 | 体感分类 | 适用层级 | 设计要求 | 案例 |
|---------|---------|---------|---------|------|
| **< 50ms** | 即时/无感知延迟 | L1 微操 | 硬件与引擎层面优化；输入缓冲区设计 | 格斗游戏帧数据响应；FPS射击判定 |
| **50-200ms** | 秒级反馈 | L1 核心操作 | 视觉/音频/触觉三通道同步；允许动画"果汁化"（Juice）装饰 | 动作游戏攻击命中；平台跳跃落地 |
| **200ms-2s** | 短延迟反馈 | L1-L2 过渡 | 需加入"预期信号"（如蓄力动画、进度环）避免玩家以为输入丢失 | 技能释放前摇；连招窗口 |
| **2s-10s** | 分钟级反馈 | L2 战术 | 必须有明确的"等待中"视觉提示；可利用延迟制造期待感 | 回合制游戏敌方行动阶段；制作等待 |
| **10s-60s** | 长延迟反馈 | L2-L3 过渡 | 需拆解为子步骤，每步给予微反馈；避免"黑箱等待" | 策略游戏回合结算；Roguelike楼层结算 |
| **> 60s** | 会话级反馈 | L3+ | 需通过中间里程碑分割；提供"进度持久化"安全感 | 关卡通关评价；对局结算 |

**设计黄金法则：**

1. **50ms 法则**：从按键到第一个视觉/音频信号，不超过 50ms。即使完整动画需要 500ms 播放，第一帧的变化必须在 50ms 内发生。
2. **反馈三明治**：先给即时微反馈（命中闪光）→ 再给过程反馈（伤害数字飞出）→ 最后给结果反馈（敌人死亡动画）。
3. **延迟≠空白**：当系统处理需要时间时（如网络同步），填充有意义的视觉/交互内容，而非空白加载。
4. **网络延迟补偿**：在线游戏中，使用客户端预测（Client-Side Prediction）+ 服务端校验（Server Reconciliation），确保玩家本地操作反馈 < 50ms，即使网络 RTT 达到 100-200ms。

### 2.4 循环嵌套关系设计方法

循环嵌套是指多个时间尺度的循环如何有机地"套"在一起，形成连贯的体验节奏。

**2.4.1 三种嵌套模式**

```
模式A：线性嵌套（Serial Nesting）
L1 → L1 → L1 → [L2结算] → L1 → L1 → L1 → [L2结算] → ... → [L3结算]
特点：简洁、易理解，适合线性关卡制游戏
案例：Super Mario（动作→动作→...→关卡结算→...→世界结算）

模式B：并行嵌套（Parallel Nesting）
L1─────────────────────────→
L2(A)──────→  L2(B)──────→
L2(C)────────────→
         [L3周期性结算]
特点：多条循环线同时运行，玩家在不同循环间分配注意力
案例：Stardew Valley（种植循环+社交循环+探矿循环并行推进）

模式C：分形嵌套（Fractal Nesting）
L1的结构自相似地出现在L2、L3中
特点：每层循环的"行动→反馈→奖励"结构保持一致，但规模不同
案例：Slay the Spire（单张牌=L1，单场战斗=L2，单层=L3，单次运行=L4——每层都是"选择→结果→适应"）
```

**2.4.2 嵌套设计的四条原则**

1. **向上传导原则**：内层循环的输出必须成为外层循环的有意义输入。
   - 正例：《Hades》每次逃脱尝试（L3）的永久货币积累影响整体叙事推进（L6）。
   - 反例：对战游戏中的"比赛MVP"成就仅是装饰，不影响任何外层进度。

2. **向下反哺原则**：外层循环的奖励应丰富内层循环的体验多样性。
   - 正例：《Slay the Spire》解锁新卡牌（L4奖励）丰富了战斗决策（L1体验）。
   - 反例：外层奖励仅是数值提升，内层游玩方式不变。

3. **独立完整性原则**：即使玩家只参与到某一层循环（如仅玩一局），也应获得完整的起承转合。
   - 正例：《Among Us》单局体验完整，不依赖任何外层循环。
   - 反例：手游新手期的前20分钟完全是引导，没有任何独立完整的循环。

4. **节奏对比原则**：相邻层级的循环应有明显的节奏差异（紧张→舒缓交替）。
   - 正例：《Hollow Knight》紧张战斗（L1-L2）→ 安静探索（L2-L3）→ 发现新区域的兴奋（L3）。
   - 反例：每一层循环的情绪强度都是恒定的平线。

## 第三章 独立游戏 vs 网游的循环差异

### 3.1 根本差异：有限体验 vs 无限运营

| 维度 | 独立游戏（有限内容） | 网游/活服（无限运营） |
|------|--------------------|--------------------|
| **设计目标** | 一次完整、令人难忘的体验 | 长期留存、持续参与、可变现 |
| **循环终点** | 明确的结局（通关/全收集） | 无终点或赛季性重置 |
| **内容来源** | 手工制作 / 有限程序生成 | 持续更新 + 深度程序生成 + UGC |
| **循环层级重心** | L1-L3（单次会话质量） | L3-L7（长期留存结构） |
| **核心指标** | 完成率、评分、口碑传播 | DAU/MAU、留存率、ARPU、LTV |
| **循环失败模式** | "玩腻了"但至少体验完整 | "倦怠了"但未完成目标，产生挫败感 |

### 3.2 有限内容：循环终止设计

独立游戏的核心挑战是**让玩家在有限的内容量内获得最大满足，并优雅地结束**。

**循环终止的四种策略：**

**策略1：叙事完结（Narrative Closure）**
- 机制：核心循环服务于故事推进，故事结束即循环自然终止。
- 案例：《Undertale》的路线走完后，游戏主动提示"这个世界已经得到幸福，请不要再重置了"。
- 适用：叙事驱动型独立游戏。

**策略2：技能天花板（Mastery Ceiling）**
- 机制：游戏难度有明确上限，玩家掌握后自然毕业。
- 案例：《Celeste》主线+B面+C面构成递进天花板，顶峰是明确的。
- 适用：纯技能型平台/动作游戏。

**策略3：组合空间耗尽（Combinatorial Exhaustion）**
- 机制：探索所有有意义的组合后完成度达到100%。
- 案例：《Baba Is You》所有谜题解开、《The Witness》所有面板完成。
- 适用：解谜游戏、收集驱动型游戏。

**策略4：情感余韵（Emotional Resonance）**
- 机制：结局的情感冲击力让玩家主动选择"不再继续"。
- 案例：《Journey》结尾的情感高潮让玩家自愿停驻；《Outer Wilds》宇宙终结的壮美感。
- 适用：体验型/氛围型游戏。

**设计要点：**
- **不要害怕结束**：独立游戏最大的优势之一就是可以有真正的结局。
- **结局≠突然截断**：通过"递减节奏"（逐步降低循环频率）让玩家自然过渡到结束状态。
- **留有"回来的理由"**：NG+、隐藏内容、成就挑战可作为"软延伸"，但不应是核心体验的必需。

### 3.3 无限运营：循环持续设计

活服游戏的核心挑战是**让核心循环在数百甚至数千小时后依然不崩塌**。

**循环持续的五大支柱：**

| 支柱 | 描述 | 实现手段 | 风险 |
|------|------|---------|------|
| **Meta变化** | 游戏环境周期性改变 | 版本平衡调整、赛季Meta轮换 | 调整过频导致玩家学习投资贬值 |
| **社交粘性** | 人际关系成为留存锚点 | 公会系统、好友对战、社区活动 | 社交压力变为义务感 |
| **内容滴灌** | 持续提供新鲜内容 | 活动、限时模式、新角色/地图 | 内容生产跟不上消耗速度（"内容跑步机"） |
| **表达系统** | 个人化定制欲望驱动 | 皮肤、成就、称号、自建内容 | 沦为炫耀消费而非有意义的表达 |
| **竞技深度** | 人与人的对抗永不重复 | PvP排位、锦标赛、电竞生态 | 匹配系统崩溃导致体验恶化 |

**关键设计原则：**

1. **赛季重置的"软清零"**：每赛季重置排名/部分进度，但保留核心资产（角色、皮肤），让玩家有"重新证明自己"的动力而非"被剥夺"的感觉。
2. **"永远差一点"机制**：通过渐近目标（如收集进度99%→发布新内容→进度降为80%）维持追求感，但不能让玩家感到"永远到不了"。
3. **循环疲劳检测与干预**：当数据显示玩家在某一循环的参与度下降时，主动引入变化（新模式、限时事件）而非加大奖励力度。

### 3.4 Roguelike / Roguelite 范式

Roguelike/Roguelite 是独立游戏中最成功的"有限内容创造无限循环"范式，值得单独深入分析。

**核心结构：**

```
┌─────────────────────────────────────────────┐
│          Meta 进度层（Roguelite 特有）        │
│  永久升级 / 角色解锁 / 叙事推进 / 图鉴解锁   │
├─────────────────────────────────────────────┤
│              单次 Run 层                      │
│  起点（弱）→ 构筑成长 → 挑战递增 → Boss/终点  │
│  [每次Run的内容由程序生成保证差异]             │
├─────────────────────────────────────────────┤
│              房间/遭遇层                      │
│  进入房间 → 战斗/事件 → 选择奖励/路径         │
├─────────────────────────────────────────────┤
│              核心操作层                        │
│  移动 → 攻击/使用道具 → 规避敌人行为           │
└─────────────────────────────────────────────┘
```

**Roguelike vs Roguelite 的循环差异：**

| 维度 | 纯 Roguelike | Roguelite |
|------|-------------|-----------|
| **死亡惩罚** | 完全清零，从零开始 | 保留部分永久进度 |
| **"再来一次"驱动力** | 纯技能精进 + 随机内容新鲜感 | 技能精进 + 永久进度推进 + 解锁新内容 |
| **循环终止条件** | 理论上无终止（纯技能挑战） | 永久进度全部解锁后可能终止 |
| **目标受众** | 核心硬核玩家 | 更广泛的中度玩家群体 |
| **代表作品** | Spelunky, Nethack, DCSS | Hades, Dead Cells, Slay the Spire |

**Roguelite 的循环可持续性公式：**

```
可持续游戏时间 ≈ 单次Run时长 × (策略组合数 + 永久解锁内容量) × 技能成长空间系数
```

**参数建议：**

| 参数 | 推荐范围 | 说明 |
|------|---------|------|
| 单次 Run 时长 | 20-45分钟 | 太短缺乏构筑深度；太长死亡惩罚过于痛苦 |
| 策略组合有效数量 | 15-50种可行Build | 低于10种很快穷尽；超过50种难以平衡 |
| 永久解锁内容量 | 50-200小时 | 是核心循环寿命的主要延伸手段 |
| 每次Run的差异度 | >60%内容随机/选择导致 | 差异度过低会导致"每把都一样"的感觉 |

### 3.5 活服（Live Service）范式

活服游戏在循环设计上有独特的结构需求。

**活服循环的三层架构：**

```
┌─────────────────────────────────────────────┐
│  运营层（赛季/大版本更新，60-90天周期）        │
│  赛季主题 → 通行证 → 排位赛季 → 大事件        │
├─────────────────────────────────────────────┤
│  习惯层（日/周节奏，推动每日登录）              │
│  每日任务 → 每周挑战 → 限时活动 → 积分兑换     │
├─────────────────────────────────────────────┤
│  体验层（单局核心循环，与独立游戏标准一致）      │
│  匹配 → 游戏 → 结算 → 奖励 → 再来一局         │
└─────────────────────────────────────────────┘
```

**活服循环设计的核心矛盾与解法：**

| 矛盾 | 描述 | 解法 |
|------|------|------|
| **新鲜感 vs 稳定性** | 玩家需要新内容，但也讨厌"版本巨变" | 80%核心不变 + 20%赛季变化；新增而非替换 |
| **核心玩家 vs 休闲玩家** | 核心玩家消耗内容快，休闲玩家跟不上 | 深度挑战（排位/天梯）与广度内容（收集/故事）分轨 |
| **付费玩家 vs 免费玩家** | 付费加速可能破坏循环公平性 | 付费仅限外观/便利，不影响核心循环的竞争平衡 |
| **短期收入 vs 长期健康** | 激进变现策略可能破坏循环节奏 | 设置变现红线（见第六章） |

**活服循环健康度的核心指标：**

- **D1/D7/D30 留存率**：衡量核心循环（D1）和习惯循环（D7/D30）的健康度。
- **单日游戏时长分布**：健康的钟形分布 vs 不健康的双峰分布（"要么不玩，要么通宵"）。
- **赛季初 vs 赛季末参与度差**：差距过大说明赛季循环的末期缺乏吸引力。
- **付费转化与留存的相关性**：付费玩家留存更高是健康的；付费后立刻流失是危险信号。

## 第四章 "再来一次"驱动力工具箱

> "再来一次"（One More Run）是核心循环成功的终极标志。以下归纳七种经过验证的驱动力范式，每种含定义、适用场景和参数建议。

### 4.1 叙事钩子（Hades 模式）

**定义：**
通过叙事内容的渐进式解锁，让每次循环都推动故事发展。玩家"再来一次"的动力来自"想知道后面发生了什么"。核心机制是将叙事碎片绑定在游戏循环中——无论成功还是失败，都会触发新的对话、情节和人物关系发展。

**运作机制：**
- 每次 Run 结束（无论胜败）触发新的叙事事件
- NPC 关系随 Run 次数和选择推进
- 叙事分支与游戏机制分支交织
- "失败"在叙事上被赋予意义（Hades 中死亡=回到冥府=推进冥府内人物关系）

**适用场景：**
- Roguelite 结构的游戏
- 有丰富世界观和角色群的项目
- 目标受众对叙事有一定需求的品类

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 每次 Run 的新叙事触发量 | 2-5个事件 | 少于2个会感觉"这把白打了"；多于5个信息过载 |
| 叙事完整通关所需 Run 数 | 30-60次 | 对应约 20-40 小时游戏时间 |
| NPC 数量 | 8-15个核心NPC | 少于8个关系网太薄；多于15个难以记住 |
| 分支叙事线数量 | 3-6条 | 保证复玩时有不同叙事路径可探索 |

**经典案例：** Hades、Hades II、Transistor（部分）


### 4.2 构筑探索（Slay the Spire 模式）

**定义：**
通过组合式构筑系统（Deck Building / Build Crafting），让每次循环产生独特的策略组合。玩家"再来一次"的动力来自"想试试另一种构筑方案"。核心是系统涌现性——相同的基础元素通过不同组合产生差异巨大的游戏体验。

**运作机制：**
- 每次 Run 从零（或低起点）开始构筑
- 随机提供的选项迫使即兴决策和适应
- 元素间存在 Synergy（协同效应），发现新组合本身就是乐趣
- 高层级策略 = 在随机性中识别和执行最优构筑路径

**适用场景：**
- 卡牌 Roguelike / 策略 Roguelike
- 有大量可组合元素的系统（技能树、装备、词缀）
- 面向享受"系统精通"的玩家群体

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 可用构筑元素总数 | 150-400个 | 少于100种组合空间不足；超过500种新手门槛过高 |
| 单次 Run 获取元素数 | 总量的 10%-25% | 保证每次 Run 只能体验一个"切面" |
| 有效 Synergy 数量 | 20-50种 | 是"发现感"的核心来源 |
| 可行 Build 原型数 | 15-40种 | 是长期复玩的核心保障 |
| 元素间交互深度层级 | 2-3层 | 1层=直接加成（太浅）；4层+=理解成本过高 |

**经典案例：** Slay the Spire、Monster Train、Balatro、Inscryption

### 4.3 零摩擦重试（Celeste 模式）

**定义：**
通过极短的"死亡→重试"延迟和精准的检查点系统，消除失败的挫败感。玩家"再来一次"的动力来自"我差一点就过了"的即时重试冲动。核心是将重试成本降到接近零，使"试错"本身成为游戏节奏的一部分。

**运作机制：**
- 死亡后瞬间复活（< 0.5秒）
- 检查点密集分布，每次失败只损失极少进度（秒级）
- 关卡设计精确，每个挑战有明确的"学习→掌握"弧线
- 失败次数不影响评价，鼓励无压力试错

**适用场景：**
- 精确平台跳跃游戏
- 需要反复尝试的高难度游戏
- "一命通关"式短关卡设计

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 死亡→重试延迟 | < 500ms | 超过1秒会显著增加挫败感 |
| 单次挑战失败的进度损失 | < 15秒的游戏内容 | 超过30秒会让玩家开始犹豫是否重试 |
| 检查点间距 | 10-30秒游戏内容 | 过密缺乏成就感；过疏增加挫败 |
| 单关卡完成时间 | 1-5分钟（含死亡重试） | 过长会产生疲劳 |
| 可选难度辅助 | 有（如 Celeste 的 Assist Mode） | 扩大受众而不稀释核心体验 |

**经典案例：** Celeste、Super Meat Boy、Hotline Miami、VVVVVV


### 4.4 解锁瀑布（Vampire Survivors 模式）

**定义：**
通过高密度、高频率的解锁事件，制造"永远有下一个东西要拿"的持续期待。玩家"再来一次"的动力来自"还有好多东西没解锁"。核心是让解锁事件以密集到近乎"溢出"的频率发生，每个解锁都提供即时的新鲜感。

**运作机制：**
- 极高密度的解锁事件（平均每 3-10 分钟一个新解锁）
- 解锁的内容立刻可用于下一次 Run
- 解锁之间存在连锁关系（解锁A → 使B可见 → 解锁B → 使C可见）
- 每次解锁都带来体验层面的可感知变化（新角色有独特玩法，不仅仅是数值皮肤）

**适用场景：**
- 轻度/中度休闲向游戏
- 内容量大但单个内容复杂度较低的项目
- 面向追求"收集满足感"的玩家群体

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 总解锁物数量 | 100-300+ | 是游戏寿命的核心指标 |
| 平均解锁间隔 | 3-10分钟游戏时间 | 超过15分钟间隔会打破"瀑布感" |
| 解锁物的体验差异度 | 中-高（至少改变一种游戏行为） | 纯数值提升的解锁缺乏新鲜感 |
| 可见但未解锁的比例 | 始终保持 30%-50% | 玩家需要能看到"还有多少要拿" |
| 隐藏解锁比例 | 10%-20% | 制造意外惊喜 |

**经典案例：** Vampire Survivors、Brotato、20 Minutes Till Dawn

### 4.5 社交故事（Lethal Company / Among Us 模式）

**定义：**
核心循环的乐趣来源不是预设内容，而是玩家之间的社交互动自然产生的"故事"。玩家"再来一次"的动力来自"上一局太好笑了/太刺激了，想再创造这样的时刻"。核心是设计一个能催化社交涌现行为的环境，而非设计固定的体验。

**运作机制：**
- 游戏规则制造信息不对称（有人知道别人不知道的事）
- 高压力环境放大情绪和反应
- 沟通（语音/文字/肢体）是核心机制的一部分
- 每局的"故事"由玩家行为自然涌现，无两局相同

**适用场景：**
- 社交推理/派对游戏
- 合作生存/恐怖游戏
- 有强社交传播需求的项目

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 最佳玩家人数 | 4-8人 | 少于4人社交张力不足；多于10人难以管理 |
| 单局时长 | 10-30分钟 | 要足够长以产生"故事弧线"，但足够短以支持多局 |
| 信息不对称程度 | 中-高 | 是社交冲突/合作的核心驱动力 |
| 沟通自由度 | 高（语音为佳） | 限制沟通会削弱社交涌现 |
| 机制学习门槛 | 低（5分钟内理解规则） | 社交游戏需要快速上手以支持不同水平的朋友群体 |

**经典案例：** Among Us、Lethal Company、Phasmophobia、Goose Goose Duck

### 4.6 时间压力的甜蜜焦虑（Stardew Valley 模式）

**定义：**
通过有限的单位时间（游戏内一天/一个赛季）和过多的可做之事，制造"时间不够用"的甜蜜焦虑。玩家"再来一次（再过一天）"的动力来自"今天还有好多事没做完，明天一定要做"。核心是让玩家始终感到时间是稀缺资源，每个时间分配决策都有机会成本。

**运作机制：**
- 游戏内时间有严格限制（如 Stardew Valley 的一天有固定时长）
- 可做之事远多于时间允许（种田+钓鱼+采矿+社交+探索...）
- 时间压力推动优先级决策（"先浇水还是先去矿洞？"）
- 时间循环终点有"结算"机制（一天结束、一个季节结束）提供节奏感

**适用场景：**
- 农场经营/生活模拟
- 时间管理类游戏
- 有多条并行活动线的项目

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 游戏内单日时长（现实时间） | 10-20分钟 | 太短则计划无法执行；太长则焦虑变为真实疲劳 |
| 可做活动数 vs 单日可完成量 | 3:1 至 5:1 | 始终有至少2/3的事情"来不及做" |
| 季节/大周期长度 | 游戏内 20-30天 | 提供中期规划和阶段感 |
| 时间压力的弹性 | 有一定容错（错过不致命） | 过于惩罚会导致焦虑从"甜蜜"变为"痛苦" |
| 自动化/效率提升 | 渐进解锁 | 让玩家感到"时间利用率在提高" |

**经典案例：** Stardew Valley、Animal Crossing、Moonlighter、Harvest Moon 系列


### 4.7 技能精进（Dead Cells / Hollow Knight 模式）

**定义：**
通过高技能天花板和精确的操作反馈，让玩家从自身能力的成长中获得满足。玩家"再来一次"的动力来自"我比上次更强了"——这里的"更强"不是角色数值，而是玩家本人的技能水平。核心是让技能差距可被清晰感知，并提供充分的空间让玩家持续精进。

**运作机制：**
- 操作系统有足够深度和精度（帧级别的输入窗口、多层级技巧）
- 难度曲线陡峭但公平（每次死亡都能归因于玩家失误）
- 成长反馈清晰（"这个Boss上次打了10次，这次3次就过了"）
- 提供进阶挑战内容（高难度模式、竞速、无伤通关等）

**适用场景：**
- 动作游戏 / 平台游戏
- 银河恶魔城（Metroidvania）
- 竞技型游戏（格斗、音游）

**参数建议：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 输入响应精度 | < 16ms（1帧@60fps） | 操作手感的基础 |
| 技能层级数量 | 4-6层 | 新手→入门→熟练→精通→大师→极限 |
| 从入门到精通所需时间 | 20-60小时 | 太短则缺乏深度；太长则中间层级玩家流失 |
| Boss/关键挑战的"重试-学习"周期 | 3-20次尝试 | 1次通过太简单；50+次通过门槛过高（除非是可选极限挑战） |
| 观察性学习比例 | 30%-50% | 不仅靠反应速度，也靠"读懂"敌人模式 |
| 可选高难度内容 | 有（隐藏Boss、高难度模式） | 为核心玩家提供持续目标而不推高基础门槛 |

**经典案例：** Dead Cells、Hollow Knight、Sekiro、Cuphead、Spelunky 2

### 4.8 驱动力组合矩阵

实际项目中通常组合使用多种驱动力。以下是经典案例的组合分析：

| 游戏 | 主驱动力 | 副驱动力 | 辅助驱动力 |
|------|---------|---------|-----------|
| **Hades** | 叙事钩子 | 技能精进 | 构筑探索 + 解锁瀑布 |
| **Slay the Spire** | 构筑探索 | 技能精进（决策） | 解锁瀑布 |
| **Celeste** | 零摩擦重试 | 技能精进 | 叙事钩子 |
| **Vampire Survivors** | 解锁瀑布 | 构筑探索（简化） | 零摩擦重试 |
| **Among Us** | 社交故事 | — | 零摩擦重试 |
| **Stardew Valley** | 时间压力的甜蜜焦虑 | 解锁瀑布 | 社交故事（NPC） |
| **Dead Cells** | 技能精进 | 构筑探索 | 解锁瀑布 |
| **Balatro** | 构筑探索 | 解锁瀑布 | 技能精进（概率判断） |

**组合原则：**

1. **主驱动力决定品类定位**：它回答"这个游戏的核心吸引力是什么"。
2. **副驱动力提供深度**：它回答"核心吸引力之外还有什么值得探索"。
3. **辅助驱动力延长寿命**：它回答"在主要内容体验完后，还有什么理由回来"。
4. **不要超过3种强驱动力**：过多的驱动力会导致设计焦点分散、每种都做不深。

## 第五章 核心循环诊断工具

### 5.1 健康循环的 5 个指标

一个健康运行的核心循环应满足以下全部五个指标：

**指标1：自愿重复率（Voluntary Repeat Rate）**
- 定义：在没有外部奖励诱导的情况下，玩家自愿再次执行循环的比例。
- 健康阈值：> 70% 的测试玩家在移除外部奖励后仍愿意继续。
- 测量方法：在原型测试中，暂时关闭所有经验值/货币/掉落，观察玩家行为。
- 解读：如果玩家只是为了奖励而重复，说明核心循环的内在吸引力不足。

**指标2：心流进入速度（Time to Flow）**
- 定义：从开始一次循环到玩家进入心流状态的平均时间。
- 健康阈值：< 循环总时长的 30%。
- 测量方法：通过玩家行为数据（操作频率稳定化）和主观报告结合判断。
- 解读：如果进入心流需要太长时间，说明循环前期的"热身"阶段设计有问题。

**指标3：决策密度（Decision Density）**
- 定义：单位时间内玩家做出的有意义决策数量。
- 健康阈值：因品类而异，但不应出现连续 > 30秒的"无决策空白期"。
- 测量方法：记录玩家每次有意义的输入（排除纯惯性操作），计算频率。
- 解读：决策密度过低→无聊；决策密度过高→疲劳。需找到品类适配的甜蜜点。

**指标4：结果方差（Outcome Variance）**
- 定义：在相同输入条件下，循环结果的差异程度。
- 健康阈值：每次循环的结果应有 > 30% 的可感知差异。
- 测量方法：对比多次循环的关键结果变量（分数、路径、获得物等）。
- 解读：方差过低→"每把都一样"的无聊感；方差过高→"完全随机"的无力感。

**指标5：情绪弧线完整性（Emotional Arc Completeness）**
- 定义：单次循环内是否具备清晰的情绪起伏（起→承→转→合）。
- 健康阈值：测试玩家能描述出至少一个"高潮时刻"和一个"紧张→释放"的节奏变化。
- 测量方法：玩后访谈 + 生理数据（心率变化、皮电反应）。
- 解读：情绪平线→缺乏记忆点；情绪全高潮→疲劳且无对比。

### 5.2 循环崩塌的症状

当核心循环出现以下症状时，说明它正在崩塌或已经崩塌：

**症状1：奖励麻木（Reward Fatigue）**
- 表现：玩家对循环的奖励不再有兴奋感，但仍在机械重复。
- 数据信号：单次循环时长不变，但会话频率下降；奖励领取率下降。
- 根因：奖励通胀——相同行为获得的奖励在"感知价值"上持续贬值。

**症状2：操作自动化（Mechanical Autopilot）**
- 表现：玩家在不需要思考的情况下机械执行循环。
- 数据信号：操作模式高度固化（每次循环的输入序列相似度 > 90%）。
- 根因：缺乏有意义的变量——环境、敌人、选项没有足够变化。

**症状3：沉没成本陷阱（Sunk Cost Trap）**
- 表现：玩家不享受循环但觉得"已经投入这么多了不能放弃"。
- 数据信号：玩家留存但 NPS（净推荐值）持续下降；社区负面情绪上升。
- 根因：外层循环（进度系统）绑架了内层循环——玩家被进度拴住而非被乐趣吸引。

**症状4：新内容依赖症（Content Treadmill）**
- 表现：每次新版本/新内容发布时活跃度飙升，但迅速回落到更低水平。
- 数据信号：版本更新后的活跃度峰值在递减，谷值也在递减。
- 根因：核心循环本身缺乏深度，完全依赖新鲜内容维持吸引力。

**症状5：鲸鱼寡头化（Whale Oligarchy）**
- 表现：游戏经济和竞技被极少数高付费玩家主导。
- 数据信号：前1%玩家贡献 > 50%收入；免费玩家流失率异常升高。
- 根因：付费系统侵入核心循环，破坏了公平性和竞争意义。

### 5.3 修复方法清单

针对上述症状的系统性修复方案：

**修复奖励麻木：**
1. 引入新的奖励维度（从纯数值转向美学/功能性奖励）
2. 增加奖励的随机性和惊喜感（但不增加总量）
3. 将部分奖励从"获得"转为"创造"（如玩家自建内容展示）
4. 引入奖励"保质期"机制，定期更新奖励池内容

**修复操作自动化：**
1. 引入新变量/Modifier打破固定模式
2. 增加环境随机性或动态事件
3. 重新审视核心操作的策略空间——是否存在绝对最优解？
4. 定期调整数值平衡，改变当前Meta

**修复沉没成本陷阱：**
1. 降低外层循环对内层循环的绑定强度
2. 提供"暂别友好"机制——离开和回来的成本都很低
3. 增强内层循环（核心玩法）本身的吸引力
4. 审计进度系统是否存在"无限延伸"的设计（永远到不了的终点）

**修复新内容依赖症：**
1. 回到核心循环，投资提升其内在深度（操作精度、策略空间）
2. 增加程序生成/UGC内容减少对手工内容的依赖
3. 引入 PvP 或社交系统作为"无限内容源"
4. 控制内容投放节奏——宁可少而精，不要多而浅

**修复鲸鱼寡头化：**
1. 严格隔离付费系统和核心循环竞争系统
2. 引入付费上限或收益递减曲线
3. 强化技能/策略在竞争中的权重，弱化数值权重
4. 为免费玩家提供有尊严的成长路径

## 第六章 核心循环与商业模型

### 6.1 F2P 付费点的嵌入位置

付费点在核心循环中的位置决定了商业化是否会伤害游戏体验。有两种根本不同的嵌入哲学：

**模式A：平行维度（Parallel Dimension）——推荐**

```
核心循环：行动 → 反馈 → 奖励 → 行动 → ...
                                          （核心循环完整运转，不受付费影响）
付费维度：  [外观商店] [便利功能] [表达系统]
            （在核心循环之外提供附加价值）
```

**特征：**
- 付费内容与核心循环在**不同维度**运行
- 不付费的玩家体验**完整的核心循环**
- 付费提供的是"锦上添花"而非"雪中送炭"
- 付费不创造竞技优势

**成功案例：**
- 《堡垒之夜》（Fortnite）：核心射击循环完全免费+公平；皮肤/通行证纯外观
- 《英雄联盟》（League of Legends）：英雄可用游戏内货币解锁；皮肤纯外观
- 《Dota 2》：所有英雄免费；付费仅限外观
- 《CS2》：武器皮肤纯外观；核心射击机制完全公平

**模式B：串联节点（Serial Node）——高风险**

```
核心循环：行动 → 反馈 → [付费墙/减速带] → 奖励 → 行动 → ...
                              ↑
                    不付费则体验降级/减速
```

**特征：**
- 付费点插入核心循环的**关键节点**
- 不付费的玩家遭遇**人为摩擦**（等待时间、体力限制、掉落率降低）
- 付费的目的是"移除障碍"而非"获得额外价值"
- 容易导致"付费即赢"（Pay-to-Win）的感知

**警示案例：**
- 体力系统（每次核心循环消耗体力，体力耗尽需付费或等待）
- 装备强化系统（强化失败概率高，付费购买保护材料）
- VIP 等级系统（付费金额直接决定游戏内特权级别）

**选择建议：**

| 因素 | 推荐平行维度 | 可考虑串联节点 |
|------|------------|--------------|
| 有 PvP 竞技元素 | 必须 | 绝对避免 |
| 面向核心玩家群体 | 强烈推荐 | 极度危险 |
| 面向超休闲群体 | 推荐 | 轻度可接受（如去广告付费） |
| 有强社区/口碑需求 | 必须 | 会引发社区反噬 |
| 纯 PvE 单人体验 | 推荐 | 轻度可接受（如 DLC 扩展内容） |

### 6.2 付费加速 vs 付费跳过的边界

**付费加速（Pay-to-Accelerate）**
- 定义：花钱缩短达成某个目标的时间，但免费玩家最终也能达成。
- 示例：经验值加成、资源加速器。
- 核心问题：加速多少算合理？

**付费跳过（Pay-to-Skip）**
- 定义：花钱直接跳过某个游戏环节或获得某个结果。
- 示例：直接购买满级角色、跳过等待时间。
- 核心问题：被跳过的内容本身是否有价值？

**边界判断框架：**

| 判断维度 | 健康 | 警告 | 危险 |
|---------|------|------|------|
| **被加速/跳过的内容本身有趣吗？** | 有趣，加速是"时间折现" | 一般，加速是"减少乏味" | 不有趣，说明内容本身是"付费催化剂" |
| **加速倍率** | < 2倍 | 2-5倍 | > 5倍（免费玩家体验被严重拖慢） |
| **付费vs免费的最终差距** | 无差距（仅时间差） | 小差距（便利性） | 大差距（能力/内容差） |
| **是否影响竞技公平** | 不影响 | 间接影响 | 直接影响 |

**设计原则：**

> 如果你需要设计"付费跳过"某段内容的功能，首先问自己：**为什么玩家想跳过这段内容？**
> - 如果答案是"因为这段内容不有趣"→ **修复内容**，而非出售跳过权。
> - 如果答案是"因为玩家时间有限但内容本身有趣"→ 这是合理的加速需求。

### 6.3 反面案例：暗黑破坏神3拍卖行

**背景：**
《暗黑破坏神3》（Diablo III）在 2012 年上线时引入了真金拍卖行（Real-Money Auction House, RMAH），允许玩家用真实货币交易游戏中的装备。

**核心循环被破坏的机制：**

```
原本设计的循环：
刷怪 → 获得装备 → 装备角色 → 挑战更高难度 → 刷更强的怪 → ...
                    ↑
                 乐趣核心

引入RMAH后的实际循环：
刷怪 → 获得装备 → 上拍卖行比价 → 发现更好的装备可以直接买 → 买装备 → ...
                                   ↑                              ↑
                              核心循环被短路                   乐趣消失
```

**崩塌过程分析：**

1. **掉落率被迫调整**：为了让拍卖行有交易价值，掉落率被显著降低。这直接伤害了核心循环中最关键的"惊喜感"。
2. **最优策略变异**：刷怪不再是获取装备的最优路径——上拍卖行购买变成了"理性最优解"。玩家的行为从"享受战斗循环"变为"打工赚金币买装备"。
3. **内在动力瓦解**：当装备有了明确的金钱价值，"获得好装备"的喜悦变成了"获得了值X元的装备"的功利计算。内在奖励被外在货币价值替代。
4. **社区撕裂**：付费玩家和免费玩家之间的体验鸿沟导致社区严重分裂。

**结局：**
暴雪在 2014 年 3 月关闭了拍卖行，并通过 2.0 补丁（"战利品2.0"系统）彻底重新设计了掉落机制——提高掉落率、增加智能掉落、引入赛季模式。这次修复被认为是"拯救了暗黑3"。

**教训：**
- 商业模型的设计必须服从核心循环的健康，而非反过来。
- 当付费系统改变了核心循环的"最优策略"时，循环必然崩塌。
- 玩家可以接受为便利/外观付费，但无法接受"核心乐趣被出售"。

### 6.4 设计红线

以下是核心循环商业化设计中**不可逾越的红线**：

**红线1：不得将核心操作乐趣置于付费墙之后**
- 违规示例：基础攻击动作需要消耗付费道具。
- 底线：核心循环的所有基本操作对所有玩家免费且完整。

**红线2：不得通过人为降低免费体验来制造付费需求**
- 违规示例：故意设计极低的掉落率/极长的等待时间，然后出售加速。
- 底线：免费玩家的核心循环节奏应当是"自然且令人满意"的，付费仅提供"更快/更多"。

**红线3：不得让付费直接决定 PvP 竞技结果**
- 违规示例：付费武器比免费武器数值高50%。
- 底线：所有影响竞技公平的元素必须通过游戏内行为获取。

**红线4：不得对未成年人使用高压变现手段**
- 违规示例：针对低龄玩家的限时折扣倒计时、社交压力付费。
- 底线：遵守所在地区的未成年人保护法规，并在此基础上自我约束。

**红线5：不得在付费后改变已购买内容的价值**
- 违规示例：玩家花钱抽到的角色在下个版本被削弱到无法使用。
- 底线：如果需要平衡调整，应提供退款/兑换机制。

**红线6：不得将随机付费（抽卡/开箱）与核心竞技强度直接绑定**
- 违规示例：最强角色/装备只能通过随机抽取获得，且有极低概率。
- 底线：所有影响核心循环的内容必须有确定性获取路径（如保底机制、直接购买选项）。

## 附录：设计速查清单

### A.1 立项阶段核心循环检查项

- [ ] **核心循环是否可以用一句话描述？**（如"射击→掩护→推进"）
- [ ] **核心循环的秒级操作（L1）是否在纸面上就具备吸引力？**
- [ ] **目标美学（MDA）是否明确？**（挑战？发现？社交？表达？）
- [ ] **核心循环的内在奖励来源是什么？**（掌控感？好奇心？创造力？）
- [ ] **竞品的核心循环是什么？我们的差异化在哪里？**
- [ ] **目标平台的输入方式是否支撑核心循环的操作精度需求？**
- [ ] **核心循环是否与目标受众的游戏习惯（会话时长、操作偏好）匹配？**
- [ ] **初步的循环层级规划（至少L1-L3）是否完成？**
- [ ] **商业模型与核心循环的关系是否初步明确？**（平行维度 vs 串联节点）
- [ ] **核心循环是否可以在2周内搭建可测试原型？**

### A.2 原型阶段核心循环检查项

- [ ] **灰盒原型中的核心循环是否好玩？**（无美术、无音效条件下测试）
- [ ] **玩家是否自愿重复循环？**（观察测试者在没有提示时的行为）
- [ ] **50ms 反馈法则是否满足？**（按键到第一个响应信号 < 50ms）
- [ ] **单次循环的情绪弧线是否存在？**（有高潮、有呼吸）
- [ ] **循环的前30秒是否能抓住新玩家？**
- [ ] **循环第100次是否仍然有变化感？**（通过高频测试验证）
- [ ] **核心循环与外层循环（L2-L3）的嵌套是否流畅？**
- [ ] **失败状态的设计是否鼓励重试？**（失败→学习的反馈链是否清晰？）
- [ ] **是否识别出了"最优策略"？如果有，它是否足够复杂/需要技能？**
- [ ] **核心循环在目标设备上的性能是否达标？**（帧率、延迟）

### A.3 量产阶段核心循环检查项

- [ ] **所有美术/音效/UI 是否强化了核心循环的反馈感？**（果汁化/Juice）
- [ ] **教学流程是否让新玩家在5分钟内理解并开始享受核心循环？**
- [ ] **L3-L4 层级的循环结构是否完整？**（会话级→日级的节奏是否设计好？）
- [ ] **核心循环是否支撑足够的内容填充量？**（关卡/角色/模式是否有足够变化空间？）
- [ ] **辅助系统（UI、菜单、存档）是否不会打断核心循环的节奏？**
- [ ] **循环中的随机性是否经过充分测试？**（最好运和最坏运情况下的体验差距是否可接受？）
- [ ] **多人模式（如有）中核心循环是否支撑不同水平玩家的同场体验？**
- [ ] **可访问性/辅助功能是否到位？**（色盲模式、操作辅助、难度选项）
- [ ] **核心循环的内存/CPU 占用是否在预算内？**（长时间循环不出现性能退化）
- [ ] **QA 回归测试是否覆盖核心循环的所有路径？**

### A.4 商业化阶段核心循环检查项

- [ ] **付费系统是否在核心循环的"平行维度"而非"串联节点"？**
- [ ] **免费玩家能否体验完整且令人满意的核心循环？**
- [ ] **付费是否影响 PvP 竞技公平性？**（如果影响，立刻修改）
- [ ] **付费加速是否保持在合理倍率内（< 2倍推荐）？**
- [ ] **抽卡/随机付费是否有保底机制和确定性获取路径？**
- [ ] **所有付费设计是否通过了"红线检查"？**（见第六章 6.4 节）
- [ ] **首充/月卡等付费设计是否不扭曲核心循环节奏？**
- [ ] **广告（如有）是否不打断核心循环的中间过程？**（仅在循环完整结束后展示）
- [ ] **付费转化率与留存率是否正相关？**（付费后留存不应下降）
- [ ] **针对未成年人的付费保护措施是否到位？**

### A.5 运营阶段核心循环检查项

- [ ] **核心循环的健康度指标是否持续监控？**（5大健康指标见第五章）
- [ ] **是否出现循环崩塌症状？**（奖励麻木/操作自动化/沉没成本/内容依赖/鲸鱼寡头——见5.2节）
- [ ] **赛季/大版本更新是否刷新了核心循环的体验？**（新变量、新Meta，而非仅新皮肤）
- [ ] **长期玩家（100+小时）的核心循环是否仍有深度可挖？**
- [ ] **新玩家加入时的核心循环体验是否因为版本迭代而变得过于复杂？**
- [ ] **社区对核心循环的反馈是否被系统性收集和分析？**
- [ ] **竞品的核心循环是否发生了变化？我们是否需要响应？**
- [ ] **核心循环的数据异常（如单次循环时长突变）是否有预警机制？**
- [ ] **外挂/作弊是否破坏了核心循环的公平性？**（反作弊系统是否有效？）
- [ ] **核心循环是否为下一个大版本的迭代预留了扩展接口？**
