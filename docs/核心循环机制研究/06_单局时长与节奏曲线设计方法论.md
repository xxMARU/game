# 06 单局时长与节奏曲线设计方法论

> 版本: v1.0 | 最后更新: 2026-03-29
> 定位: 为单局/Session驱动型游戏提供时长规划与节奏设计的完整工具箱

---

## 1. 核心理念

单局时长（Session Length）和节奏曲线（Pacing Curve）是玩家「心流体验」与「再来一局」冲动的底层引擎。设计目标不是「让玩家玩更久」，而是「让每一秒都有意义，并在最佳时刻结束」。

**核心公式（Peak-End Rule应用）:**
```
Session满意度 = 峰值体验强度 × 结束时正面情绪 / 总时长感知
```

## 3. Jesse Schell Interest Curve 理论应用

### 3.1 理论核心

Jesse Schell在《The Art of Game Design》中提出**Interest Curve（兴趣曲线）**：

1. **Hook（钩子）** — 开局数秒内必须抓住注意力，兴趣快速爬升
2. **Rising Interest（渐升）** — 持续升级的挑战和新鲜感维持上升斜率
3. **Peaks & Valleys（峰谷交替）** — 高强度巅峰与低强度喘息交替出现，避免疲劳
4. **Climax（高潮）** — 全局最高强度体验点，通常在70-85%进度处
5. **Resolution（收束）** — 高潮后短暂降温，给予成就感和闭合感

### 3.2 Interest Curve 设计参数

```
理想兴趣曲线关键锚点:
├── 0-5%进度:    Hook强度 ≥ 70%峰值（必须立即吸引）
├── 5-20%进度:   第一个mini-peak，强度约50-60%
├── 20-40%进度:  稳步攀升，引入新机制/元素
├── 40-60%进度:  中段peak，强度约75-85%，随后valley降至40-50%
├── 60-80%进度:  第二段攀升，复杂度和stakes持续提高
├── 75-85%进度:  CLIMAX，强度100%
├── 85-95%进度:  Resolution/奖励收割
└── 95-100%进度: "再来一次"过渡窗口
```

### 3.3 峰谷比最佳实践

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 峰:谷强度比 | 2:1 ~ 3:1 | 峰值强度是谷值的2-3倍 |
| 峰间间隔 | 3-7分钟(动作类) / 10-20分钟(策略类) | 品类依赖 |
| 谷持续时间 | 峰的30-50% | 太短=无喘息，太长=无聊 |
| 总峰数 | 3-5个(30分钟局) | 峰太多会疲劳 |
| Climax位置 | 70-85%总进度 | 过早=虎头蛇尾，过晚=无Resolution |

## 4. Valve Left 4 Dead AI Director 四阶段强度循环

### 4.1 AI Director 系统概述

Valve在Left 4 Dead (2008)中开创性地使用**AI Director**动态调节游戏节奏。系统实时监测玩家压力指标（血量、弹药、击杀率、移动速度），动态调整敌人生成和物资投放。

### 4.2 四阶段强度循环模型

```
      强度
  100%|        ╱╲
      |       ╱  ╲         ╱╲
   75%|      ╱    ╲       ╱  ╲
      |     ╱      ╲     ╱    ╲
   50%|    ╱    BUILD╲   ╱  BUILD
      |   ╱    UP    ╲ ╱   UP
   25%| PEAK→  ╱  RELAX  PEAK→
      |  ╱    ╱
    0%|───────────────────────────→ 时间
      BUILD  PEAK  RELAX  BUILD  PEAK
       UP                  UP
```

**四阶段详解:**

| 阶段 | 持续时间 | 强度范围 | 行为 |
|------|---------|---------|------|
| **Build-Up（积蓄）** | 45-90秒 | 30%→70% | 渐增敌人密度，收紧资源，提示Boss |
| **Peak（巅峰）** | 15-30秒 | 80-100% | Horde事件/Tank/Witch，极限压力 |
| **Relax（喘息）** | 30-60秒 | 10-30% | 极少敌人，投放补给，安全屋视线 |
| **Transition（过渡）** | 15-30秒 | 30-40% | 下一波前的环境预兆 |

### 4.3 Director 关键参数

```python
# AI Director 核心参数（逆向工程估计值）
INTENSITY_DECAY_RATE = 0.025      # 每秒强度自然衰减
INTENSITY_BUILDUP_RATE = 0.015    # 每秒积蓄增长
PEAK_THRESHOLD = 0.75             # 触发Peak的强度阈值
RELAX_THRESHOLD = 0.25            # 进入Relax的强度阈值
MIN_RELAX_DURATION = 30           # 最短喘息秒数
MAX_RELAX_DURATION = 60           # 最长喘息秒数
HEALTH_WEIGHT = 0.3               # 团队血量对强度的权重
AMMO_WEIGHT = 0.15                # 弹药状态权重
PACE_WEIGHT = 0.25                # 推进速度权重
DAMAGE_TAKEN_WEIGHT = 0.3         # 近期受伤权重
```

### 4.4 Director模型在其他游戏中的应用

| 游戏 | 应用方式 | 效果 |
|------|---------|------|
| Deep Rock Galactic | 动态Swarm波次 | 类似4阶段，加入环境事件 |

## 5. 通用节奏强度曲线数学模型

### 5.1 基础模型

```
I(t) = I_base × [0.3 + 0.7 × (t/T)^1.2] × [1 + A × sin(2π × t/P)]
```

**参数定义:**

| 参数 | 含义 | 推荐范围 | 说明 |
|------|------|---------|------|
| `I(t)` | t时刻的体验强度 | 0-1 | 输出值 |
| `I_base` | 基础强度系数 | 0.4-0.7 | 品类基线：动作0.6，策略0.4 |
| `t` | 当前时间 | 0-T | 局内经过时间 |
| `T` | 单局总时长 | 品类依赖 | 设计目标时长 |
| `A` | 振荡幅度 | 0.15-0.35 | 峰谷对比度，动作类0.3，休闲0.15 |
| `P` | 振荡周期 | 3-10分钟 | 一个完整峰谷周期 |

### 5.2 模型解读

- **`0.3 + 0.7 × (t/T)^1.2`**: 包络线，确保整体从30%基线向100%渐升（指数1.2使后半段加速）
- **`1 + A × sin(2π × t/P)`**: 在包络线上叠加正弦振荡，创造峰谷节奏
- **合并效果**: 越到后期，峰越高谷也越高，自然形成Climax

### 5.3 品类参数预设表

| 品类 | I_base | A | P(分钟) | T(分钟) | 包络指数 |
|------|--------|---|---------|---------|---------|
| 超休闲 | 0.5 | 0.1 | 0.5 | 1-2 | 1.0(线性) |
| BR射击 | 0.5 | 0.25 | 5 | 25 | 1.3 |
| MOBA | 0.4 | 0.3 | 8 | 30 | 1.5 |
| Roguelike动作 | 0.6 | 0.3 | 4 | 25 | 1.2 |
| 恐怖生存 | 0.3 | 0.35 | 7 | 45 | 1.1 |
| 竞速 | 0.7 | 0.15 | 1 | 3 | 1.0 |

### 5.4 高级变体

**Boss Rush修正:**
```
I_boss(t) = I(t) × [1 + B × exp(-(t - t_boss)² / σ²)]
```
在Boss时刻 `t_boss` 处叠加高斯脉冲，B=0.3-0.5，σ=30-60秒。

**动态难度修正:**
```
I_adaptive(t) = I(t) × [1 + α × (Performance - Target)]
```
α=0.2-0.4，根据玩家表现偏离目标值做线性补偿。

## 6. "再来一次"过渡窗口设计

### 6.1 核心原理

「再来一次」冲动发生在单局结束后的**10-30秒过渡窗口**内。这个窗口的设计目标：

1. **最小化退出摩擦** — 减少让玩家"想起该走了"的停顿
2. **最大化重开诱惑** — 展示进步、悬念、新内容预告
3. **维持情绪惯性** — 不要让积极情绪冷却

### 6.2 Hades 死亡→重开全链路计时拆解

Hades被公认为"再来一次"设计的标杆。以下是精确链路分析：

| 阶段 | 时间 | 内容 | 设计意图 |
|------|------|------|---------|
| 死亡动画 | ~1.5秒 | 角色倒下+冥河吞没 | 快速，不拖沓 |
| 死亡画面 | ~2秒 | 击杀者+本次数据闪现 | 信息回报（我差一点！） |
| 冥河过渡 | ~3秒 | 漂浮动画+加载 | 视觉连贯，掩盖加载 |
| 神殿着陆 | ~2秒 | Zagreus爬出血池 | 叙事连续性（不是Game Over） |
| NPC对话 | 5-30秒 | 1-2段新对话 | **叙事回报**：死亡推动剧情 |
| 永久升级 | 10-20秒 | 花暗黑资源强化 | **进度回报**：我变强了 |
| 武器选择 | 5-15秒 | 换武器+暗黑恩赐 | **新鲜感**：下一局会不同 |
| 出发动画 | ~2秒 | 冲出神殿 | **前向动量** |
| **总计** | **~30-75秒** | | **零等待感的"加载+决策+叙事"** |

**关键设计原则:**
- ❌ 没有"返回主菜单" — 死亡即重开，是叙事的一部分
- ❌ 没有长Loading屏 — 用叙事动画掩盖加载
- ✅ 每次死亡都有新对话 — 400,000+字剧本支撑
- ✅ 花费资源产生"沉没成本期待" — "我刚升级了，试试效果"

### 6.3 不同品类的过渡窗口参数

| 品类 | 理想过渡时间 | 核心钩子 | 反例 |
|------|-------------|---------|------|
| Roguelike | 30-60秒 | 永久升级+新Build预览 | 过渡>90秒流失率+15% |
| BR | 15-30秒 | 即时数据+快速匹配 | PUBG早期>60秒等待 |
| 竞技对战 | 10-20秒 | 段位变化+对手预告 | - |
| 三消/休闲 | 3-8秒 | 下一关预览+星级悬念 | 长广告打断=卸载 |
| 关卡制动作 | 15-30秒 | 评级+隐藏收集物提示 | - |

## 7. POI间距设计

### 7.1 旷野之息 POI间距数据

《塞尔达传说：旷野之息》的开放世界POI（Point of Interest）设计被认为是行业标杆：

**核心数据:**
- **平均POI间距**: 步行30-90秒可达下一个兴趣点
- **视线可见范围**: 任意位置可见2-3个未探索POI
- **POI密度**: 约900+个收集物/神庙/据点分布在84km²地图
- **平均每平方公里POI数**: ~10.7个

**POI层级体系:**

| 层级 | 类型 | 平均间距(步行秒) | 参与时长 | 密度 |
|------|------|------------------|---------|------|
| 微型 | 克洛格种子 | 15-30秒 | 5-15秒 | 极高(900个) |
| 小型 | 敌人营地/宝箱 | 30-60秒 | 1-5分钟 | 高 |
| 中型 | 神庙 | 60-180秒 | 5-20分钟 | 中(120+个) |
| 大型 | 村庄/马厩 | 180-600秒 | 15-60分钟 | 低(15+个) |
| 超大型 | 神兽/主线地牢 | 特定位置 | 30-90分钟 | 极低(4个) |

**30-90秒法则解读:**
- **30秒**是「觉得无聊想退出」的心理阈值
- **90秒**是「发现新东西之前能容忍的最长空白」
- 在这个窗口内至少提供一个微型或小型POI，维持探索动力
- 关键：不是所有POI都需要高价值，低成本的"小发现"（如种子）足以维持节奏

### 7.2 POI间距设计通用原则

```
最大步行空白时间 ≤ 90秒
视线内可见下一个POI: 始终保证
POI价值层次: 微(5s参与) / 小(1-5min) / 中(5-20min) / 大(20min+)
微型POI密度 ≥ 总POI的60%
```

## 8. 六大设计反模式警示表

| # | 反模式 | 表现 | 后果 | 案例 | 修正 |
|---|--------|------|------|------|------|
| 1 | **无限延长局** | 无硬性结束机制，局时长方差极大 | 沉迷→疲劳→弃游；排位体验差 | Dota 2超时赛(70min+局) | 加入缩圈/时间限制/加速机制 |
| 2 | **平坦节奏** | 全局强度恒定，无峰谷变化 | 感觉像"一直在跑步机上" | 劣质跑酷无限模式 | 按Interest Curve植入峰谷 |
| 3 | **虚假高潮** | Climax放在50%进度，后半段拖尾 | "最好的部分已经过了"感觉 | RPG中段Boss>终段Boss | Climax定位75-85%进度 |
| 4 | **过渡断裂** | 局结束→主菜单→排队→Loading→选角 | 每步都是退出机会 | 早期PUBG死亡后全链路>2min | 学Hades：死亡=叙事，零停顿 |
| 5 | **强制等待** | 体力耗尽/复活CD/开箱计时器 | 惩罚性停顿破坏心流 | 手游体力系统无缓冲 | 提供替代活动/预告下次内容 |
| 6 | **节奏一刀切** | 核心/休闲/新手用同一节奏曲线 | 核心玩家嫌慢，新手嫌快 | 无难度选择的固定关卡 | 动态Director或难度分层 |

## 9. 设计验证清单

### 9.1 上线前必检项

- [ ] **Session时长CV(变异系数) < 目标值?** — 超休闲<20%，竞技<30%，RPG<60%
- [ ] **Interest Curve有几个可辨识的峰?** — 30分钟局≥3个峰
- [ ] **Hook在前5秒/前30秒内触发?** — 首次体验录像验证
- [ ] **Climax位于70-85%进度?** — 时间戳标记确认
- [ ] **再来一次过渡窗口 ≤ 目标时长?** — Roguelike≤60s，竞技≤20s
- [ ] **最长无事件空白 ≤ 90秒?** — 开放世界必测
- [ ] **数学模型I(t)实际拟合度?** — 用遥测数据回归验证

### 9.2 数据驱动迭代指标

| 指标 | 采集方式 | 健康范围 | 警报阈值 |
|------|---------|---------|---------|
| 中位Session时长 | 客户端遥测 | ±20%设计目标 | 偏差>30% |
| Session间间隔 | 登录时间戳 | <4小时(日活用户) | >8小时 |
| 局内放弃率 | 中途退出追踪 | <10%(竞技)/<20%(休闲) | >30% |
| 重开率(死亡后) | 事件追踪 | >60%(Roguelike) | <40% |
| 节奏满意度(调研) | 局后问卷 | >4.0/5.0 | <3.5 |
| 峰值时刻识别 | 心率/GSR生物数据 | 与设计峰点±15%吻合 | 偏移>25% |

### 9.3 Playtest节奏验证Protocol

1. **5人以上内测，全程录屏+面部表情捕捉**
2. **标记每位测试者的「情绪峰值时刻」和「无聊/困惑时刻」**
3. **将时刻映射到I(t)曲线上，检查是否与设计意图吻合**
4. **计算实际峰位置 vs 设计峰位置的MAE(平均绝对误差)**
5. **若MAE > 15%总时长，进入节奏调优迭代**
