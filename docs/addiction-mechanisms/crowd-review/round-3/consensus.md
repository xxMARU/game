## 1. 系统定位（三轮收敛）

> **本系统是一个"数据稀缺场景的数值预飞行检查器"（Numerical Pre-flight Checker for Data-Scarce Scenarios）——在缺乏直接真人行为数据的游戏开发场景中，使用计算行为学Agent模型对参数化的游戏设计空间进行预筛选。系统输出的是"值得投入真人测试资源去验证的候选参数配置"——是假设清单，不是设计方案。**

### 三轮定位演进

| 轮次 | 定位表述 | 变更理由 |
|------|---------|---------|
| R1 | "给定一款已有核心玩法的休闲手游，在其数值参数空间内搜索高参与度配置的辅助筛选工具" | 首次定位 |
| R2 | "计算行为学筛选工具"/"数值预飞行检查器" | 增加认识论定位（E）+产品化名称（A） |
| **R3** | **"数据稀缺场景的数值预飞行检查器"** | 增加适用场景约束（A+C对用户画像的分析） |

### 适用/不适用场景（R3新增——R1/R2未涉及）

| 场景 | 适用？ | 理由 |
|------|--------|------|
| 新游戏立项（无历史数据） | ✅ 核心场景 | 唯一可用的预筛方法 |
| 现有游戏引入全新机制 | ✅ 重要场景 | 历史数据不可直接迁移 |
| 跨品类/跨市场迁移 | ✅ 补充场景 | 数据可迁移性低 |
| 成熟游戏日常运营调优 | ❌ 不适用 | 大厂数据驱动方法更优（C论证） |
| 付费/社交/视听设计优化 | ❌ 不适用 | 超出系统覆盖范围（C论证，R1已确认） |
| 独立开发者自建系统 | ⚠️ 不推荐 | ROI负值；推荐使用SaaS版（A论证） |

## 2. 核心架构决策更新

以下仅列出**相对R2有变更**的决策。R2中未变更的决策维持R2原判。

### 决策2.3-再修正：退出模型Phase 1新增session_goal

**R3推翻R1/R2的session_goal时间线。Phase 1引入简化版session_goal。**

简化版session_goal规格：
- 每个Agent在session开始时从LogNormal分布采样一个"目标步数"
- 达到目标步数后，退出概率跳升至5×基线水平
- 如果Agent处于"心流状态"（连续3步以上获得正RPE），目标步数延长15%
- 目标步数分布参数可被进化优化（作为第9个可优化参数）

**变更理由（R3推翻R1/R2的论证）**：
- C的关键数据：实际游戏中60-75%的退出是目标驱动的，纯累积阈值+泊松中断只覆盖15-25%的退出模式
- R1/R2将session_goal推迟到Phase 2的理由是"Phase 1复杂度已高"
- R3的解法：引入session_goal的同时**砍掉Phase 1的参数交互效应扫描**（E建议的700次额外评估），实现工时对冲
- 退出模型的真实性提升 > 参数交互分析的边际价值

### 决策2.5-再修正：Phase 1双退出模型

**R3新增要求：Phase 1实现2套独立退出模型。**

- 主模型：阈值累积+泊松中断+简化session_goal（完整版）
- 验证模型：纯累积不满意度阈值模型（极简版，2天实现）
- 两套排名Spearman ρ>0.5作为Phase 1软性验收标准
- ρ<0.5说明退出模型选择对结果有重大影响→Phase 2重点研究

**变更理由**：E的SPOF分析——退出模型是唯一决定session_length的模块，无冗余=单点故障

### 决策2.7-再修正：HSCD重命名为PSD+新增RSV

**R3推翻R1/R2的"HSCD因果检测"命名和方法。**

| 组件 | 原名称 | R3名称 | 功能 |
|------|--------|--------|------|
| 参数微扰检测 | HSCD（分层随机因果检测） | **PSD（参数敏感性检测）** | ±15%微扰→方向一致性+效应存在性 |
| 排名稳定性验证 | 无 | **RSV（排名稳定性验证）** | 独立Agent群重新训练评估Top 10设计 |
| 结构因果模型 | 无 | **SCM（Phase 2应当通过）** | 预定义DAG+do-calculus因果效应估计 |

**变更理由**：
- B从do-calculus角度的论证：当前方法不满足因果推断的形式化定义（总效应≠直接效应，无法区分环境效应/特质效应/Agent学习效应）
- E的FMEA（FM-09，RPN=384）：PSD会被进化式Reward Hacking绕过，RSV提供额外检测层
- 名称误导在学术发表和产品宣传中有实际风险

### 决策2.14（R3新增）：engagement_ratio Phase 1角色降级

**R3推翻R2的三级阶梯过滤器。Phase 1中engagement_ratio降级为观测变量。**

| | R1 | R2 | **R3** |
|---|---|---|---|
| Phase 1角色 | 连续变量，含在session_quality中 | 三级阶梯过滤器（<0.3淘汰） | **仅记录+标注+不参与进化选择** |
| 淘汰功能 | engagement_ratio<0.4淘汰 | engagement_ratio<0.3淘汰 | **Phase 1不淘汰** |
| 激活条件 | Phase 1起 | Phase 1起 | **Phase 2效度验证后激活** |

具体执行：
- engagement_ratio在Phase 1正常计算并记录
- engagement_ratio<0.3的设计标注⚠️"参与质量待验证"
- 低engagement_ratio设计**不进入CMA-ES精英集**（不影响搜索方向）
- 但**保留在档案中**（不删除、不淘汰）
- Phase 2真人校准时回溯验证：被标注设计是否真的低质量？

**变更理由**：
- B的核心论证：用未验证效度的指标做不可逆淘汰，在方法论上是错误的
- Phase 1不产出可部署的设计，假阳性（错误淘汰好设计）的代价>假阴性（保留坏设计）的代价
- E的FMEA（FM-08，RPN=280）：engagement_ratio测量无效是第3高风险

## 3. 适应度函数更新

### 3.1 Phase 0——无变化
```
fitness_v0 = median_session_length(agent_group, design_config)
```

### 3.2 Phase 1——四项技术修正

```
fitness = session_value_norm^0.40 × robustness^0.20 × safety^0.25 × novelty^0.15

其中：
  session_value = session_length × exp(-session_length / τ)   ← R3新增：倒U型映射
  session_value_norm = minmax_normalize(session_value, [0.1, 1.0])  ← R3新增：归一化
  robustness = minmax_normalize(agent_type_agreement × parameter_stability, [0.1, 1.0])
  safety = sigmoid_clip(1 - exploit_penalty) × psd_coherence   ← R3修改：sigmoid替代硬截断
  novelty = 1 + α × distance_to_archive(design, historical_archive)

τ初始值=40（Agent步数单位，Phase 1通过真人映射数据标定）
α初始值=0.2
权重分配：w1=0.40, w2=0.20, w3=0.25, w4=0.15（Σ=1.0，与R2一致）
```

**R3变更明细**：

| # | 修改 | R2原方案 | R3方案 | 来源 |
|---|------|---------|--------|------|
| F1 | session_length → session_value倒U型 | session_length越长越好（S1软截断） | `sl × exp(-sl/τ)` 有最优点 | C（业务数据支撑） |
| F2 | 因子归一化 | 原始值直接取几何平均 | min-max归一化到[0.1, 1.0] | B（尺度压缩分析） |
| F3 | 下限截断方式 | 硬截断（x<0.1→x=0.1） | sigmoid软截断（低分区保持梯度） | B |
| F4 | 交叉验证fitness | 无 | 第二套纯中位数session_value排名 | E（SPOF缓解） |
| F5 | engagement_ratio | 三级阶梯过滤器 | 仅记录+不进化选择 | B+E（效度未验证） |

**Phase 1交叉验证规则**：
- fitness_primary（上述加权几何平均）用于CMA-ES进化选择
- fitness_secondary（纯中位数session_value排名）用于独立验证
- 两套排名的Top 10设计重叠度<50%时触发警报，需人工审查fitness_primary的因子权重

### 3.3 Phase 2——在R2基础上新增

- engagement_ratio：根据Phase 2真人效度验证结果决定是否恢复为过滤器/连续变量
- 如果效度>0.3：恢复三级阶梯过滤器，阈值根据真人数据重新标定
- 如果效度<0.3：engagement_ratio需根本性重构

## 12. R3评审的元观察

### 12.1 三轮评审的角色演进

| 轮次 | 主要角色类型 | 关注焦点 | 对系统的态度 |
|------|------------|---------|-------------|
| R1 | 技术架构师+学术研究者 | 架构可行性、理论基础 | 建设性乐观 |
| R2 | 工程实践者+方法学家 | 实现细节、统计严谨性 | 审慎优化 |
| **R3** | **用户/利益相关者** | **落地可行性、实际价值、外部风险** | **冷静质疑** |

### 12.2 三轮的渐进成熟度

- R1：定义了"系统应该做什么"（What）
- R2：定义了"系统应该怎么做"（How）
- R3：定义了"系统应该不做什么"（What Not）和"为谁做"（For Whom）

**R3的最大贡献不是技术改进，而是场景约束和用户定义。** 这使得整个方案从"理论上可行的系统"向"对特定用户有价值的产品"迈进了一步。

### 12.3 仍然存在的结构性不确定性

经过三轮评审，以下问题仍然无法在纯模拟/理论层面回答，**必须通过实验才能解决**：

1. Agent群的排序准确率到底是多少？（Phase 0实验回答）
2. session_goal参数对Agent行为的影响有多大？（Phase 1实验回答）
3. engagement_ratio到底测量了什么？（Phase 2真人校准回答）
4. 系统推荐在真人身上的迁移率是多少？（Phase 2实验回答）

**这些问题定义了项目的4个实验性里程碑。每个里程碑的结果可能推翻前面所有轮次的共识。这就是为什么Go/No-Go门控如此重要——它们是"理论遇见现实"的检查点。**
