## 1. HSCD因果检测方案的深层问题

### 1.1 回顾：HSCD是什么

R1提出、R2确认的HSCD（Hierarchical Stochastic Causal Detection）方案：
- 对2-3个参数做±15%微扰
- 观察session_length变化方向是否一致
- 不一致则降低causal_coherence
- 全部无效但高分的标记为可疑

**这不是因果推断。这是敏感性分析（sensitivity analysis）。** 名字起得太大了。

### 1.2 为什么"±15%微扰"不是因果干预

真正的因果干预（intervention）要求do-calculus意义上的do(X=x)——切断X的所有父节点影响，单独设定X的值，观察Y的变化。在这个系统中：

- 我们改变的是游戏参数（如奖励频率从7→8.05）
- 观察的是Agent群的median_session_length变化
- **问题：Agent群本身有内部状态演化**。改变奖励频率不仅直接影响session_length，还改变了Agent的Q值分布、退出阈值的累积路径、心理特质的触发频率

这意味着我们观察到的效应是**总效应（total effect）**，不是**直接效应（direct effect）**。当我们说"提高奖励频率导致session_length增加"，我们无法区分：
- 路径A：频率↑ → Agent获得更多正RPE → 延迟退出（直接机制效应）
- 路径B：频率↑ → 疲劳累积速率变化 → 退出阈值到达时间变化（间接特质交互效应）
- 路径C：频率↑ → Agent探索策略变化 → 发现了新的高奖励状态序列 → 延迟退出（Agent学习效应）

**如果系统的目标只是"找到好参数"，区分不了也没关系。但如果我们要判断Agent的反应是否"像人类"，不区分这三条路径是危险的。** 因为人类几乎不走路径C（人类不会在每局游戏中重新学习最优策略）。

### 1.3 HSCD真正能检测什么

诚实地说，HSCD能做到三件事：
1. **方向性一致性检验**：参数增大 → session增/减？方向是否stable？（有用，但trivial）
2. **效应存在性检验**：参数变化是否有统计学显著的效应？（有用，是baseline requirement）
3. **异常高分检测**：高session_length但对所有参数微扰都不敏感 → exploit信号（有用，是关键贡献）

但HSCD**做不到**：
- 因果机制识别（哪个心理特质驱动了效应）
- 真实效应量估计（±15%微扰的线性外推不可靠）
- 交互效应的因果方向（A×B交互中，谁是调节变量谁是中介变量）

### 1.4 我的修正建议

**将HSCD降级命名为"参数敏感性检测"（Parameter Sensitivity Detection, PSD）**，不再使用"因果"一词。同时新增一个真正的因果分析层：

**Phase 2引入结构因果模型（SCM）**：
- 预先定义参数→特质激活→行为→退出的DAG（有向无环图）
- 用do-calculus计算可识别的因果效应
- 对不可识别的路径（如路径C中的Agent学习效应），通过**冻结Agent权重**做消融实验

具体来说：
- 冻结Agent的Q表/策略网络，只改变游戏参数 → 观察纯环境效应
- 冻结游戏参数，只改变Agent初始状态 → 观察纯Agent效应
- 两者的差值 = 交互效应

**成本估算**：每个设计多跑2轮（冻结Q值+冻结参数），约2倍额外计算量。远低于R1中被否决的"全量消融"（400倍），但远高于当前HSCD（0.5-1倍）。作为Phase 2而非Phase 1的要求，这个成本是可接受的。

## 2. Fitness函数的统计性质分析

### 2.1 加权几何平均的问题

R1/R2的Phase 1 fitness函数：
```
fitness = session_length_norm^0.4 × robustness^0.20 × safety^0.25 × novelty^0.15
```

加权几何平均有两个重要的统计性质需要审视：

**问题1：对数空间的隐式假设**

加权几何平均等价于 `exp(Σ w_i × log(factor_i))`。这假设各因子在对数空间中线性组合是合理的度量。但：
- session_length_norm 的分布可能是近似正态的（经过归一化后）
- novelty 的分布取决于设计空间的拓扑结构，通常是右偏的
- safety 是一个bounded [0.1, 1.0] 的变量

**在对数空间中，[0.1, 1.0]范围的变量被极度压缩在[-2.3, 0]区间，而novelty（范围[1.0, ?]）的对数是无界正值。** 这意味着safety因子的区分度被系统性压缩，而novelty的区分度被系统性放大。即使权重是0.25 vs 0.15，safety的实际影响力可能小于novelty。

**修正建议**：对所有因子做z-score标准化后再取几何平均，或者直接使用加权算术平均（简单且可解读性强）。

**问题2：下限截断的副作用**

R1设定了下限：session_quality≥0.1, robustness≥0.1, safety≥0.1, novelty≥1.0。

截断在0.1处意味着safety=0.05和safety=0.10的设计得到相同的fitness。**这在进化优化中会导致"悬崖效应"——safety一旦低于0.1，进化压力消失，这些设计可能在其他维度上被优化出高分。** 应改为连续衰减函数（如sigmoid截断：`max(0.01, 1/(1+exp(-10*(x-0.1))))`），保持低分区域仍有梯度。

### 2.2 engagement_ratio的三级阶梯设计评估

R2将engagement_ratio改为前置过滤器（<0.3淘汰 / 0.3-0.5警告 / ≥0.5正常）。

**统计学角度的问题**：

这是一个人为设定的阈值，没有任何经验数据支撑"0.3"和"0.5"的选择。更重要的是，**engagement_ratio本身的构念效度还没有经过验证**（R2将效度检验推到了Phase 2的G2-5/G2-6）。

在效度未验证的情况下用它做前置淘汰，逻辑上等价于：**用一个我们还不确定是否测量了我们想测量的东西的指标，来做不可逆的设计淘汰决策。**

我的建议：
- Phase 1不淘汰任何设计（engagement_ratio仅记录和标注）
- Phase 2的真人校准同时验证engagement_ratio的效度
- 效度>0.3后才激活淘汰功能

### 2.3 CMA-ES的收敛性问题

R2选择CMA-ES作为Phase 1的进化优化器，这是合理的。但有一个被忽略的问题：

**CMA-ES在8维空间中的典型收敛速度约200-500次评估**（Hansen & Ostermeier, 2001）。每次评估需要运行300个Agent×完整会话，成本不低。但更关键的是：**CMA-ES假设fitness landscape是局部光滑的。**

如果fitness landscape有不连续性（比如engagement_ratio的0.3阈值导致的悬崖，或者某些参数组合触发Agent行为模式的突变），CMA-ES的协方差矩阵估计会被污染，导致搜索方向错误。

**验证建议（Phase 1必须做）**：
- 在CMA-ES收敛后，对最优解邻域做密集采样（±5%网格，8^3=512点）
- 检查fitness landscape的局部光滑性（相邻点的fitness差异分布）
- 如果发现不连续性占比>10%，需要切换到对不连续性鲁棒的优化器（如NSGA-II或Bayesian Optimization with GP-Hedge）

## 3. 效应量估计的可复现性

### 3.1 核心挑战：多少次独立运行才够？

Phase 0的关键指标是Cohen's d>0.5。但这个d的估计本身有多大的方差？

设好/差设计各跑100个Agent：
- 如果真实d=0.5，100vs100的双样本t检验的power约0.70（不够！标准要求0.80）
- 如果真实d=0.8（更乐观），power约0.95（够了）
- **如果真实d正好在0.5附近，我们有30%的概率在单次运行中得到d<0.5然后错误地终止项目**

R2的G0-6要求27组拉丁超立方采样来检验超参数稳定性。但没有要求**对同一设计的多次独立评估**来检验效应量估计的稳定性。

**建议新增G0-8**：对"已知好"和"已知差"设计各做5次独立评估（不同随机种子），Cohen's d的95%置信区间完全在>0.5的区域内。如果置信区间跨0.5，说明我们的检测力不够，需要增加Agent数量或减少Agent行为方差。

### 3.2 随机种子的影响链

在这个系统中，随机性来自至少5个源头：
1. Agent的初始Q值/策略参数
2. Agent的心理特质采样（λ, k, fatigue参数）
3. 游戏环境的随机事件（三消棋盘生成、宝箱掉落）
4. Agent的exploration（ε-greedy或策略网络的采样噪声）
5. 退出模型中的泊松过程

**如果不固定1-4只变5，我们观察到的session_length方差中，有多少来自"有趣的"源（退出决策）vs"无趣的"源（随机种子噪声）？**

这就是ICC（组内相关系数）分析的经典应用场景。建议Phase 0必须报告：
- ICC(1)：单次评估的可靠性
- ICC(k)：k次评估均值的可靠性
- **目标：ICC(5)>0.80**——即5次独立运行的均值作为"真实fitness"，可靠性达到0.80

### 3.3 多重比较问题

Phase 0要评估10组设计配置，Phase 1要从进化种群中选Top 5。**当我们从N个设计中选Top K时，我们面临经典的多重比较问题。**

具体来说：如果10个设计的真实fitness完全相同（null hypothesis），纯靠随机波动也会产生"最好"和"最差"的排名。在Cohen's d=0.5的效应量下，**排名前3的设计中，大约有1个是假阳性（真实排名不在前3）。**

**在Phase 1中这个问题更严重**：CMA-ES在200-500次评估后选出的"最优"可能只是"在那次随机种子下碰巧好"。

**缓解方案**：
- Phase 0：对Top 3设计做交叉验证（不同Agent种群重新评估），确认排名稳定性
- Phase 1：CMA-ES找到的最优解必须在3组独立Agent种群上重新评估，取一致排名

## 4. R3特有发现：被忽略的"测量标准"问题

### 4.1 session_length的时间映射是未解决的基础问题

R2的N4提到了"session_length时间映射标定"，但只分配了2天工时。**这是严重低估。**

Agent的一个"session"是多少步？一步对应真人的多少时间？这不是一个简单的线性映射问题，因为：
- 真人的决策速度随session进行而变化（开始快→中间慢→疲劳后又变快/直接退出）
- Agent是瞬时决策，没有"思考时间"
- 真人会被打断（来电话、到站了、老板来了），Agent不会

**如果映射做错了，所有基于session_length的fitness计算、Go/No-Go标准、甚至Cohen's d的估计都建立在错误的基础上。**

建议将此升级为Phase 0的一个正式工作包（至少1周），包括：
- 从真实游戏日志中提取session结构（步数分布、思考时间分布、中断模式）
- 建立"Agent步数→真人分钟"的非线性映射函数
- 验证映射后的Agent session分布与真实分布的KS检验
