# Round 3 辩论第三轮：最终仲裁

**仲裁者**：Round 3 最终仲裁者  
**日期**：2026-03-29  
**输入**：5份R3独立评审 + 综合分析 + 挑战反驳 + R1共识 + R2共识  
**任务**：对每个悬而未决的问题做最终裁定，形成R3共识的基础

---

## 裁定原则

1. **硬证据优先于理论论证**——C的实际数据（60-75%目标驱动退出）优先于理论推导
2. **工程约束是真实约束**——时间线不能无限延长
3. **错误的代价不对称**——假阳性（淘汰好设计）比假阴性（保留坏设计）代价更高（在Phase 1阶段）
4. **R3的角色是"用户/利益相关者视角"**——优先考虑落地可行性

---

## 裁定1：系统定位

**最终裁定：采纳挑战者修正——"数据稀缺场景的数值预筛工具"。**

不采纳"冷启动工具"（太窄），不维持"辅助筛选工具"（太宽）。

适用场景精确定义：
1. 新游戏立项（无历史数据）→ 核心场景
2. 现有游戏引入新机制（历史数据不可直接迁移）→ 重要场景
3. 跨品类/跨市场迁移（数据可迁移性低）→ 补充场景

**不适用场景（必须明确标注）**：
- 有充分真人数据的成熟游戏运营调优
- 有专业数据团队+ABTest平台的大厂日常参数优化
- 任何涉及付费体系、社交系统、视听设计的优化

**决策依据**：
- C的论证（大厂有更好的数据驱动方法）是正确的，但挑战者的修正也对——"新机制引入"不是冷启动但也缺乏直接参考数据
- A的论证（SaaS化后才有价值）决定了商业模式——不是卖给大厂替代ABTest，而是卖给"没有数据能力的团队"或"大厂的新项目组"

---

## 裁定2：session_goal

**最终裁定：Phase 1引入简化版session_goal。交互效应扫描推迟到Phase 2。**

采纳挑战者方案：
- Phase 1的session_goal：对数正态采样目标步数 + 达标后退出概率5×基线跳升 + 心流状态下目标延长15%
- Phase 1砍掉E建议的交互效应扫描（700次额外评估）
- 净增工时≈0

**决策依据**：
- C的数据（60-75%目标驱动退出）是R3中最强的新证据之一
- 退出模型是多位评审者识别的最关键组件，改进它的优先级高于参数交互分析
- 交互效应扫描可以在Phase 2和真人校准一起做，边际成本更低

---

## 裁定3：engagement_ratio在Phase 1的角色

**最终裁定：降级为"记录+标注+不参与进化选择"。不做淘汰。**

采纳挑战者折中方案：
- engagement_ratio在Phase 1中仅作为观测变量
- 低engagement_ratio设计正常参与fitness排序，但标注⚠️
- 低engagement_ratio设计不进入CMA-ES的精英集（不影响搜索方向，但保留在档案中）
- Phase 2用真人数据回溯验证engagement_ratio的预测效度

**决策依据**：
- B的逻辑论证是决定性的——用未验证效度的指标做不可逆决策是方法论错误
- 但完全不用engagement_ratio也不行——挑战者的"不进化选择"是好的折中

**相对R2的变更**：R2的"三级阶梯过滤器（<0.3淘汰/0.3-0.5警告/≥0.5正常）"被降级为"观测+标注+不进化选择"。这是R3对R2的一个**实质性推翻**，需要充分论证：
- R2的淘汰阈值0.3没有经验数据支撑
- 在效度验证前淘汰设计的风险>保留低质量设计的风险（因为Phase 1不产出部署方案）

## 裁定4：HSCD→PSD+RSV

**最终裁定：重命名+新增RSV，采纳挑战者方案。**

- HSCD重命名为PSD（参数敏感性检测）——B的论证是决定性的
- 新增RSV（排名稳定性验证）：Top 10设计用独立Agent群重新训练评估
- Phase 2 SCM作为"应当通过"（非硬性要求）——采纳挑战者倾向

**决策依据**：
- B从do-calculus角度的论证不可反驳——当前方法不满足因果推断的形式化定义
- 名称误导有实际风险（学术发表、产品宣传）
- RSV弥补了E识别的FM-09（PSD被绕过）的风险

---

## 裁定5：fitness函数

**最终裁定：采纳挑战者混合方案，四项修改全部采纳。**

1. ✅ 保持加权几何平均
2. ✅ 所有因子min-max归一化到[0.1, 1.0]
3. ✅ 下限截断改为sigmoid软截断
4. ✅ session_length内置倒U型映射：`session_value = sl × exp(-sl/τ), τ初始=40`
5. ✅ 第二套纯中位数session_value排名作为交叉验证

**决策依据**：
- B的尺度压缩分析技术上正确
- C的倒U型映射有业务数据支撑
- E的双验证成本极低但价值高
- 4项修改没有增加系统复杂度，只是修正了fitness函数的实现细节

## 裁定6：监管风险值

**最终裁定：上修到0.25。**

- 概率：0.25（D建议0.35，挑战者修正0.25）
- 影响：1.0
- 风险值：0.25
- 排名：从R2的#8升至**#5**

**决策依据**：
- D的政策趋势分析是有价值的，但挑战者正确指出监管过程非线性
- 0.25是对当前证据的最佳估计——比R1/R2的0.20更合理，比D的0.35更审慎

**附加决策**：
- D建议的"监管合规层"采纳为Phase 2硬性要求
- D建议的"审计日志"采纳为Phase 1软性要求
- D建议的engagement/compulsion框架独立可交付物——维持R2的S6

## 裁定9：B建议的新增标准

### G0-8（B建议）：效应量置信区间

**最终裁定：采纳，但修改实现方式。**

- 不要求5次独立评估（成本过高：5×100Agent×10配置=5000次评估）
- 改为**Bootstrap置信区间**：对已有的100Agent评估结果做1000次bootstrap重采样
- 要求Cohen's d的95% bootstrap CI下界>0.3（不是>0.5）
- 理由：bootstrap不增加计算成本；下界>0.3已经足够说明效应不是随机噪声

### ICC分析（B建议）：随机种子影响评估

**最终裁定：采纳为Phase 0的"应当通过"标准。**

- 对"已知好"设计做3次独立运行（不同随机种子全部重置）
- 报告ICC(3)
- 目标：ICC(3)>0.70（比B建议的ICC(5)>0.80更宽松，因为只跑3次）
- 不通过则需要在Phase 1增加Agent数量或减少Agent行为随机性
