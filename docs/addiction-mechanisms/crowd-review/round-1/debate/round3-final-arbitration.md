## 1. 系统定位（一句话）

> **本系统是"给定一款已有核心玩法和Game Feel的休闲手游，在其数值参数空间内搜索高参与度配置"的辅助筛选工具；它不是端到端的游戏设计系统，不是人类策划的替代品，不是可直接部署的产品生成器。**

**决策依据**：
- 5位评审者全部同意系统应定位为辅助工具而非自主系统（共识6）
- C明确指出系统只能覆盖约35-45%的会话时长驱动力，Game Feel/社交/视听等维度是结构性盲区
- E将其精确定位为"A/B测试的前筛漏斗"——从百万级设计空间筛选到十级候选
- 挑战者进一步确认：系统在其覆盖范围内强于预期（55-65%排序准确率），在覆盖范围外弱于预期（25-35%市场预测率），不取平均

## 2. 核心架构决策（逐项YES/NO）

### 决策2.1：LLM→RL Agent解耦架构是否保留？
**YES。**  
5/5评审者一致确认这是正确的架构决策。用RL Agent行为统计替代LLM主观判断，阻断了LLM不确定性向评估端传播。此为无争议共识。

### 决策2.2：DSL是否在Phase 1实现为完整编译器？
**NO。Phase 1使用JSON配置文件，硬编码三消游戏引擎核心规则，DSL仅控制数值参数。**  
- A论证了DSL编译器实质上是一个游戏引擎+约束求解器，4-6周内不可能完成
- 挑战者警告：纯数值参数可能导致Agent行为方差过小，因此验证标准必须检测非线性响应
- DSL扩展功能推迟到Phase 2+，Architect的DSL扩展权力在Phase 1完全禁用

### 决策2.3：心理特质层是否保留10种特质？
**NO。Phase 0仅实现3种：损失厌恶、延迟折扣、疲劳。Phase 1扩展到5种。Phase 2扩展到8种。**  
- A指出10种特质独立叠加会产生人类不可能的行为模式
- B逐条审查发现多处公式问题（敏化无限增长bug、损失厌恶固定值、耐受模型缺正负不对称）
- 挑战者强调质量>数量——先修好3种，比做坏10种更有价值

### 决策2.4：Agent数量是否保持500？
**NO。Phase 0=100，Phase 1=300，Phase 2=600。**  
- 关键原则：**模型多样性优先于数量扩张**
- Phase 1引入2套独立退出模型，Phase 2引入3套独立心理特质公式体系
- 采样策略从网格搜索改为拉丁超立方+人口分布先验（B建议）
- 20%的Agent注入行为噪声模拟人类非理性（挑战者建议）

### 决策2.5：退出决策模型是否改为"阈值累积+随机中断"？
**YES。这是P0级必修项。**  
- B论证"每步quit_prob"产生指数分布的会话时长，与真实heavy-tailed分布（log-normal/power-law）结构性不匹配
- D的攻击分析证明当前模型可被"无限循环"exploit
- 验证标准：生成的会话时长分布必须与Bauckhage 2012发表的真实数据在分布形态上匹配

### 决策2.6：优化目标是否从"成瘾性"改为"参与度"？
**YES。彻底放弃"成瘾性最大化"表述。**  
- E论证在当前全球监管趋势下（EU DSA、中国防沉迷、美国KOSA），显式以"成瘾性"为优化目标存在真实法律风险
- C指出"成瘾性≠好玩"，系统倾向优化compulsion而非engagement是方向性错误
- 挑战者给出了可操作方案：通过行为签名区分engagement和compulsion（见适应度函数设计）

### 决策2.7：是否引入因果干预测试？
**YES，但采用低成本方案（分层采样因果检测），不做全量消融实验。**  
- D论证静态统计检测指标会在50-200代内被进化优化绕过
- 挑战者指出全量消融成本是正常评估的400倍，完全不可行
- 采纳挑战者的HSCD方案：随机微扰（±15%）→ 因果强度估计 → 仅对可疑设计做深度消融
- 额外计算成本：前100轮约3-5倍，100轮后降至1.5-2倍

### 决策2.8：Architect的搜索引导是否保留？
**YES，但权力必须受约束。**  
- 至少30%的新设计必须来自纯随机变异，不受Architect引导
- Phase 1禁止DSL扩展
- Phase 2起Architect提议的新机制必须通过A/B有效性证明才能纳入

### 决策2.9：是否要求真人校准？
**YES。Phase 2必须包含小规模真人测试（≥50人），作为硬性Go/No-Go门控。**  
- 5/5评审者均下调了迁移成功率估计，无真人校准下最乐观估计也只有50-65%（E）
- C和E均建议尽早引入真人验证回路
- Phase 0和Phase 1不要求真人（成本约束），但Phase 2开始前必须有

### 决策2.10：是否引入新颖性搜索？
**YES，从Phase 1开始。**  
- D论证fitness landscape中的宽浅盆地会吸引所有trajectory收敛到"标准三消+每日签到+进度条"的无创新设计
- fitness函数中加入novelty_bonus = distance_to_archive(current_design, historical_archive)
- 具体权重在Phase 1中通过实验标定

## 3. MVP规格（精确数字）

### 3.1 Phase 0 — 最小可验证闭环（MVP）

**核心问题**：Agent群对已知好设计和已知差设计的区分能力有多强？

| 组件 | 规格 | 决策理由 |
|------|------|---------|
| 游戏引擎 | 硬编码标准三消（匹配检测、消除、重力填充、特殊块），不可修改规则 | A建议+消除DSL变量 |
| 可调参数 | **8个**（见下表） | 挑战者定义的最小集合 |
| RL算法 | **2种**：Q-Learning + Actor-Critic | 最基础的model-free对 |
| Agent数量 | **100个**（2算法 × 50参数配置） | 足够检测Cohen's d>0.5的效应量 |
| 心理特质 | **3种**：损失厌恶（分布采样λ~LogNormal）、延迟折扣（k∈[0.01,1.0]）、疲劳（含恢复机制） | 最成熟+B修正后的公式 |
| 退出模型 | **阈值累积+泊松中断**混合模型 | B的P0级改进，不可省略 |
| 进化循环 | **无**——手动创建10组设计配置 | 消除Architect变量，纯测Agent |
| 因果干预 | **无**——用金标准好/差对比替代 | 挑战者：Agent连好/差都分不出时讨论因果干预为时过早 |
| 伦理约束 | **无**——MVP不产出可用设计 | 伦理在系统产出可review设计时激活 |
| LLM组件 | **无** | 纯Agent有效性验证 |

**8个核心数值参数**：

| # | 参数 | 范围 | 必要性 |
|---|------|------|--------|
| 1 | 奖励频率（每N步一次奖励事件） | 3-20 | 核心强化学习回路 |
| 2 | 奖励方差（大小奖励比率） | 1:1 - 1:20 | 间歇强化效应 |
| 3 | 难度斜率（每关难度增幅%） | 2-15% | 心流与挫败平衡 |
| 4 | 体力上限（可连续玩的关卡数） | 3-30 | 会话时长硬约束 |
| 5 | 体力恢复速率（分钟/点） | 5-60 | 回归动机 |
| 6 | 失败惩罚（失败后损失进度%） | 0-50% | 损失厌恶激活 |
| 7 | 连胜奖励倍率 | 1.0-5.0 | 热手效应 |
| 8 | 每日任务奖励占比（占总收益%） | 0-40% | 习惯养成回路 |

## 4. 适应度函数设计

### 4.1 Phase 0 适应度（简化版，用于MVP验证）

```
fitness_v0 = median_session_length(agent_group, design_config)
```

Phase 0不需要复杂fitness——核心目标是验证Agent对参数变化的敏感性方向和幅度。仅用中位数session_length作为单一指标，避免引入未经验证的复杂因子。

### 4.2 Phase 1 适应度（完整版）

```
fitness = session_quality^w1 × robustness^w2 × safety^w3 × novelty^w4

其中：
  session_quality = normalized_session_length × engagement_ratio
  robustness = agent_type_agreement × parameter_stability
  safety = (1 - exploit_penalty) × causal_coherence
  novelty = 1 + α × distance_to_archive(design, historical_archive)

初始权重：w1=0.4, w2=0.25, w3=0.25, w4=0.1
```

**各因子定义**：

**engagement_ratio**（挑战者方案）：
- Engagement行为签名：高action_diversity + 高strategic_depth + 对reward_removal中等敏感 + 自然退出模式
- Compulsion行为签名：低action_diversity + 高sunk_cost_sensitivity + 对reward_removal极度敏感 + action_quality递减
- `engagement_ratio = E_score / (E_score + C_score)`
- **硬约束：engagement_ratio < 0.4的设计直接淘汰，不进入排名**

**agent_type_agreement**：
- 使用加权Kendall τ，各算法按人口代表性赋权（B建议）
- 不要求全体一致，要求排序一致性

**parameter_stability**：
- 对Top参数做±10%扰动后fitness变化幅度的负值
- 排除对单一极端参数的过度依赖

**causal_coherence**（HSCD方案）：
- 对2-3个随机参数做±15%微扰
- 如果微扰后session_length变化与参数变化方向不一致（如提高奖励但session缩短），causal_coherence降低
- 如果所有参数微扰均无效果但session_length很高，标记为可疑并触发深度消融

**exploit_penalty**：
- 保留原方案4指标（action_diversity、state_coverage、reward_variance、quit_distribution）
- 但从硬阈值改为连续评分
- 超过警戒线的设计自动进入深度因果检测队列

**novelty_bonus**：
- 使用设计的**行为指纹**（Agent行为统计向量）而非参数值计算距离
- 维护历史设计档案库，每50轮归档一次
- α初始值=0.2，可通过实验调整

### 4.3 因子组合方式

采用**加权几何平均**而非纯乘法（挑战者建议），避免单因子为零导致fitness崩塌：

```
fitness = ∏(factor_i ^ w_i)  where Σw_i = 1
```

各因子做下限截断：session_quality≥0.1, robustness≥0.1, safety≥0.1, novelty≥1.0

### 4.4 Phase 2 适应度（扩展版）

在Phase 1基础上新增：
- `multi_session_score`：7天模拟的总参与时长（非单日最大值），检测"短期高但长期倦怠"
- `vulnerability_score`：脆弱群体Agent子集的成瘾风险指标，作为惩罚项
- `cultural_robustness`：跨文化Agent群组间的一致性

## 5. 伦理框架

### 5.1 硬约束（不可商量，违反则自动阻断）

| # | 约束 | 执行机制 | 激活阶段 |
|---|------|---------|---------|
| H1 | **engagement_ratio硬下限**：fitness函数中engagement_ratio<0.4的设计直接淘汰 | fitness计算时自动过滤 | Phase 1起 |
| H2 | **退出路径清晰度**：所有设计必须保留无摩擦退出路径；"退出壁垒"模块重命名为"回归动力"模块，禁止增加退出成本 | DSL schema层面禁止exit_barrier>0.3 | Phase 1起 |
| H3 | **脆弱群体保护**：Agent群必须包含"高冲动+高损失厌恶"的脆弱画像（k>0.8, λ>3.5），当设计对该画像的compulsion签名超过阈值时自动标红 | Analyst模块自动检测 | Phase 2起 |
| H4 | **成瘾风险报告**：每个进入人类审核的设计必须附带自动生成的成瘾风险评估，量化各成瘾机制的贡献度 | Analyst输出强制包含 | Phase 2起 |
| H5 | **禁止对未成年人优化**：系统不得用于优化面向<18岁用户的产品参数 | 使用协议层面的法律约束 | 全阶段 |

### 5.2 软约束（强烈建议，可在记录理由后覆盖）

| # | 约束 | 理由 |
|---|------|------|
| S1 | 单次会话时长优化上限设为45分钟——超过此值的session_length不再贡献正向fitness | E的建议+行业数据（超长session与次日留存负相关） |
| S2 | 多日模拟中，日均使用时长>120分钟的Agent比例不应超过10% | WHO游戏障碍标准的量化代理 |
| S3 | 系统输出的设计推荐必须以"人类策划筛选→真人A/B测试验证"的流程使用，禁止跳过人类审核直接部署 | 系统定位为辅助工具，不是自主系统 |
| S4 | 每个季度对系统产出进行一次伦理审计，评估产出设计的总体compulsion/engagement倾向 | 防止系统随时间漂移 |

### 5.3 叙事框架转换

- **禁止使用的术语**：成瘾性优化、让玩家停不下来、退出壁垒、沉没成本陷阱
- **替代术语**：参与度优化、延长优质体验、回归动力、投入感知
- 这不仅是公关措辞——它反映了优化目标的根本转向：从"削弱用户自主控制"到"提升用户体验质量"

## 7. Go/No-Go标准

### 7.1 Phase 0 → Phase 1 门控

**必须全部通过（AND逻辑）：**

| # | 标准 | 度量 | 阈值 |
|---|------|------|------|
| G0-1 | Agent群能区分已知好/差设计 | 好/差配置session_length的Cohen's d | **>0.5** |
| G0-2 | Agent排序与人类金标准一致 | 好/差排序一致的Agent比例 | **≥80%** |
