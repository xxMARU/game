## 一、项目目标

用户希望构建一个**完全无监督、自闭环**的系统，该系统能够：
1. 自动生成游戏机制设计
2. 自动评估设计的成瘾性效果
3. 自动迭代优化
4. 最终输出高成瘾性的休闲手游设计方案

核心约束：
- **无人类介入**（或极少介入）
- **无真人测试数据**作为初始锚点
- 游戏品类：**休闲手游**（如三消类）
- 核心优化指标：**会话时长**（让玩家每次打开后停不下来）
- Token/算力无限制

## 二、讨论历程与关键决策

### 2.1 初始讨论：LLM能否模拟人类感受来测试游戏成瘾性

**结论**：LLM不能"感受"成瘾，但能"推理"成瘾。
- LLM擅长：模式识别（将游戏设计映射到已知成瘾机制）、知识检索、组合
- LLM部分可靠：基于已知规律的方向性预测（增/减判断可靠，具体数值不可靠）
- LLM不行：模拟真实心理体验过程（没有状态演化、没有身体、概率拟合≠因果理解）

**五大会话时长成瘾机制**（针对休闲手游）：
1. **心流锁定**：背侧纹状体自动化 + PFC抑制降低 → 难度动态曲线、操作反馈感
2. **间歇强化**：VTA→NAc相位性DA释放 → 随机掉落、宝箱、分数爆发
3. **进度诱惑**：NAc shell预期性放电 → 进度条差一格、"再玩一局就升级"
4. **损失厌恶**：杏仁核+脑岛过度响应 → 连胜中断、限时道具过期
5. **蔡格尼克效应**：dlPFC对未完成目标持续激活 → 关卡中途、任务链未结束

### 2.2 验证工具方案讨论

提出了四模块验证系统：
- **模块1 - 机制解构器**：将自然语言设计映射到成瘾机制原语
- **模块2 - 虚拟玩家群模拟**：8种典型休闲玩家画像（P1通勤杀时间型~P8轻度尝鲜型）
- **模块3 - 量化评分卡**：多维评分+对标案例+弱点诊断
- **模块4 - 迭代优化器**：自动生成改进变体+预测提升幅度

### 2.3 RL Agent引入

**关键洞察**：人脑多巴胺系统与RL算法是数学同构的（Schultz 1997）

| 大脑 | RL算法 |
|------|--------|
| 多巴胺放电 | 奖赏预测误差(RPE) |
| VTA→NAc突触强化 | 价值函数更新 V(s) ← V(s)+α·δ |
| DMS→DLS习惯形成 | model-based → model-free转移 |
| 耐受 | 奖赏基线上移 |
| 敏化 | 特定线索价值过估 |

LLM与RL的互补：
- LLM：能解释"为什么"，不能预测"会不会"
- RL Agent：能预测"会不会"，不能解释"为什么"

### 2.4 无监督闭环的核心挑战

三大问题：
1. **Reward Hacking**：生成器找到模拟器的漏洞而非真正有效设计
2. **LLM自证循环**：两个LLM共享偏见，互相确认，无新信息注入
3. **Agent过拟合**：过拟合到特定Agent参数，换配置后失效

### 2.5 "中间层转译"方案讨论

用户提出：用LLM将游戏表现转译为"脑信号"，再基于脑信号驱动RL Agent。

**结论**：架构思路正确（解耦游戏空间和决策空间），但LLM不是正确的转译工具。
- LLM生成的"脑信号"数值是编造的（不确定、不一致、无真实基础）
- 会导致RL Agent学到"LLM编数字的规律"而非"人脑规律"
- 正确做法：用有文献支撑的数学公式做转译（计算神经科学模型）

## 三、当前最完整方案：自闭环成瘾性优化系统

### 3.1 总架构

```
Architect（LLM主控）
  ├── 假设生成：从数据中提出语义假设
  ├── 搜索引导：用知识库剪枝降低搜索空间
  └── 设计空间扩展：提议新DSL模块

Compiler（编译器）
  └── DSL描述 → 可运行的游戏环境

Population（Agent群）
  ├── 算法多样性：Q-Learning, SARSA, Actor-Critic, Model-Based, Dyna-Q, Habit-RL
  ├── 参数多样性：learning_rate × discount_factor × exploration = 125种/算法
  ├── 心理特质层：损失厌恶、延迟折扣、耐受/适应、对立过程、敏化、疲劳、挫败退出、好奇心、沉没成本、蔡格尼克效应
  └── 退出决策模型：每步选择"继续玩"vs"退出"

Arena（竞技场）
  └── Agent群在游戏环境中实际运行，产生行为数据

Analyst（分析师）
  ├── 适应度评估：session_length × agent_type_agreement × parameter_robustness × (1-exploit_penalty)
  └── 反作弊：action_diversity、state_coverage、reward_variance、quit_distribution
```

### 3.2 DSL（领域特定语言）设计

游戏机制的参数化描述语言，覆盖：
- 核心消除规则（匹配规则、特殊块、连锁）
- 关卡系统（难度曲线、目标类型、步数限制）
- 奖励系统（宝箱、combo、连续登录）
- 参与钩子（每日任务、限时活动、进度预告）
- 退出壁垒（中途惩罚、连胜警告、会话时长奖励）
- 元系统（收集、声望）

关键原则：
- 每个字段都可被自动修改
- 严格类型约束（不产生逻辑矛盾）
- 嵌套结构支持涌现

### 3.3 Agent群心理特质层（数学公式，非LLM猜测）

| 特质 | 数学实现 | 文献基础 |
|------|---------|---------|
| 损失厌恶 | loss_weight = 2.5 × gain_weight | Kahneman 1979 前景理论 |
| 延迟折扣 | V = A/(1+k*D), k∈[0.01,0.5] | Mazur 1987 双曲折扣 |
| 耐受/适应 | baseline += α*(reward-baseline) | Solomon 1980 |
| 对立过程 | net = a_process - b_process, b累积增强 | Solomon 1974 |
| 敏化 | cue_value *= (1+sensitize), 不衰减 | Robinson 1993 |
| 疲劳 | fatigue += f(time), performance *= (1-fatigue) | — |
| 挫败退出 | quit_prob += frustration × personality | — |
| 好奇心 | novelty_bonus = η/√visit_count | Kakade 2002 |
| 沉没成本 | quit_cost += invested_time × sunk_w | Arkes 1985 |
| 蔡格尼克 | unfinished_value += progress% × zeigarnik_w | Zeigarnik 1927 |

### 3.4 迭代流程

1. Architect生成20个种子设计（DSL格式）
2. Compiler编译 → 20个可运行游戏环境
3. Arena运行 → 每环境×500 Agent → 行为数据
4. Analyst评估 → 适应度排名+异常检测
5. Architect决策 → 精英保留+交叉变异+假设驱动修改+随机探索
6. 生成新20个设计 → 回到步骤2
7. 每50轮检查DSL扩展需求，每100轮全量稳健性评估

### 3.5 设计空间的三个层级

- **层级1-调参数**（能做）：固定机制种类，搜索最优数值配置
- **层级2-调机制组合**（能做）：固定核心玩法，搜索模块排列组合（~100万种）
- **层级3-发明新玩法**（目前做不到）：从零创造游戏规则

### 3.6 可行性评估

- Agent群认为好 → 人类也觉得好的概率：~65-75%
- 比纯LLM评估（~40-50%）高
- 比资深策划直觉（~50-60%）略高
- 比随机设计（~10-15%）远高

### 3.7 工程落地估算

- Phase 1（4-6周）：简化DSL+90Agent+基础心理特质层+API调用Architect
- Phase 2（3-4月）：完整DSL+500Agent+全心理特质+异常检测+可视化
- Phase 3（6月+）：多品类DSL+Agent自适应校准+Architect多轮推理优化

## 四、待评审的核心问题

评审subagent需要从各自角度评估以下问题：

1. **总体可行性**：这套自闭环系统在工程上是否可实现？关键技术瓶颈在哪？
2. **Agent群作为人类代理的有效性**：RL Agent + 数学心理特质层能在多大程度上代理真人行为？盲点在哪？
3. **DSL的表达力vs约束力平衡**：DSL太简单则搜索空间受限，太复杂则编译器难以保证正确性，如何平衡？
4. **LLM Architect的角色边界**：LLM做假设生成和搜索引导是否可靠？会不会注入偏见？
5. **Reward Hacking防御**：当前的多指标+异常检测方案是否足够？有什么更好的防御策略？
6. **收敛性与创新性的矛盾**：系统会不会过早收敛到"教科书式正确但无创新"的设计？如何保持探索？
7. **从模拟到真实的迁移**：Agent认为好的设计，部署到真人后的gap有多大？如何缩小？
8. **伦理考量**：自动化生成"最大成瘾性"设计的伦理边界在哪？是否需要内置约束？
